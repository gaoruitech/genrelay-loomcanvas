# 常见问题

[English](faq.md)

自己部署实例的人常会遇到的问题。画布使用上的问题，应用内的教程（编辑器里「更多 ⋯ → 使用教程」）里有单独的常见问题，也可以看[使用指南](user-guide.zh-CN.md)。

## 模型与成本

### 节点上显示「成本未知」

这个模型没有与当前参数对得上的价格。LoomCanvas 不自带任何价格：它无从知道你的上游向你收多少钱。

1. 打开「模型管理」页，选中服务商，找到模型，点「设置价格」。
2. 填上你实际支付的单价。价格随分辨率或时长变化的，在「价格随什么变化」里选对应的项，每个档位填一行。

价格表里没有当前分辨率或时长对应的那一行，同样是「成本未知」。按 token 计价的对话模型在运行前显示未知，运行后如果上游返回了 token 用量才有成本。没有价格的模型照样可以运行。详见[服务商](providers.zh-CN.md#价格)。

### 模型下拉是空的，或者提示「还没有可用的模型」

按这个顺序检查：

1. 「模型管理」页：有没有添加服务商，卡片上是否显示已启用、Key 已设置？点一下卡片上的「测试连接」。
2. 还是这一页，选中那个服务商：它的模型开关是否打开？
3. 节点类型对不对？视频编辑节点只列出视频编辑模型。OpenAI 和 Gemini 这两家服务商完全不提供视频模型。
4. 大语言模型节点：列出所有已启用的对话模型。高瑞服务商有五个（三个纯文本，两个可读图片）；服务商列表里没有的对话模型，可以在「模型管理」页作为自定义模型添加。选了纯文本模型时，节点的图片输入口会变灰，已连接的图片不会发送。
5. 视频分析节点：只列出能输入视频的对话模型。目前是高瑞服务商下的 `gemini-3.5-flash-c`，以及高瑞服务商下的自定义对话模型。OpenAI 和 Gemini 的对话模型不会出现在这里。

模型列表不取决于上游连不连得上：它就是服务商自带的模型列表加上你的自定义模型。

### 需要的模型没出现，或者列出了不该有的

每家服务商支持哪些模型是一份固定的列表，随 LoomCanvas 一起发布。不会去读上游的模型列表，也不会根据模型的名字去猜。

- 缺了：打开「模型管理」页，选中那个服务商，点「添加自定义模型」。模型名按上游要求的原样填写，并选择类型（图片或对话）。不能添加自定义视频模型。
- 多了：在「模型管理」页把它的开关关掉。
- 从上一个版本升级之后，自定义模型的类型可能不对，或者用过的模型没有带过来，见[从上一个版本升级](providers.zh-CN.md#从上一个版本升级)。

### 重新运行节点会再计一次费吗

会。每次运行都会向上游提交一个新任务。对已经有结果的节点重新运行前，画布会先让你确认。之前的结果留在节点的历史版本里。

### 这里的金额和真实账单一致吗

不一定。金额是按你填的价格、在提交运行时算出来的（对话模型则按返回的 token 用量算）。以上游的账单为准。失败的运行在这里不计花费，即使上游已经为它收了钱。

## 素材

### 运行失败，提示「…需要公网可访问的地址…」

有些输入只能以地址的形式交给上游：高瑞图片模型的参考图（图生图）、视频编辑的原视频、部分视频模型的参考图、对话里的视频。上游必须能从公网下载这个地址。

两种解决办法选一个：

- 把 `PUBLIC_URL` 设成实例的公网地址（例如 `https://canvas.example.com`），并确认它真的能从公网访问；或者
- 把文件存到公网上能访问到的 S3 兼容的桶里（「设置 → 存储」）。桶里的文件交给上游时用的是有效期一小时的预签名地址，所以既不需要 `PUBLIC_URL`，桶也不用公开。

Endpoint 只在内网里能用的桶（`http://minio:9000`、内网 IP）不算：它的地址绝不会交给上游。请设置 `PUBLIC_URL`，或者把这个桶的 S3 接口以公网域名发布出去并设置 `S3_PRESIGN_ENDPOINT`，见[存储](storage.zh-CN.md#什么算公网可达)。

用 `PUBLIC_URL` 这个办法时，画布上已有的文件不用重新上传：它们的地址是站内相对地址，交给上游时才拼上 `PUBLIC_URL`。改用桶并不会搬走已经在本地磁盘上的文件；这些文件仍然需要 `PUBLIC_URL`，或者重新上传一次。`localhost`、`minio` 这样的容器名和内网地址永远不算公网地址。见[服务商](providers.zh-CN.md#素材怎么送到上游)和[存储](storage.zh-CN.md#给上游模型的参考素材)。

### 从另一台电脑打开，图片全是破图

不管文件在本地磁盘上还是在桶里，都是按站内相对地址（`/files/<key>`）保存的，从哪个地址打开应用就从哪个地址加载。所以当前版本存下的文件不应该出现这个问题，不管 `PUBLIC_URL` 是什么。

早期版本保存的画布仍可能出现：那时存的是绝对地址，例如 `http://localhost:3000/files/…`，另一台电脑的浏览器访问不到。把这些文件重新上传，或者重新运行节点。见[部署](deployment.zh-CN.md#public_url)。

### 缩略图是怎么回事，为什么有的没有

- 节点里显示的是一张小的 WebP 缩略图（最长边 512 像素），不是原图；查看大图和下载用的始终是原图。
- 缩略图在上传文件或转存结果时生成。缺的那张会在第一次被请求时现做一份并保留。本地磁盘和桶都一样；缩略图和它的原图存在同一处。
- 只有 PNG、JPEG、WebP、BMP、AVIF 图片有缩略图。视频、GIF、HEIC 没有，直接显示原文件。
- 很小的上传图片（最长边不超过 512 像素）自己就是自己的缩略图。
- 外部地址的图片，以及早期版本保存的画布里用桶的绝对地址引用的图片，推不出缩略图地址，直接显示原图。这只是慢一些，不是坏了。

### 上传失败，或提示文件太大

有两道限制，取较小的：

| 限制 | 默认 | 在哪里 |
| --- | --- | --- |
| 服务端，每个文件 | 50 MB | `MAX_UPLOAD_MB`。画布从服务端读到这个值，超过的文件在上传前就会被拦下。 |
| 反向代理 | 各不相同（nginx 不配置时是 1 MB） | `client_max_body_size` 或类似配置 |

如果收到 `413`，而且看起来不是 LoomCanvas 的提示，那就是代理返回的。只接受图片和视频文件，按内容判断。

### 结果下载失败：「不允许访问内网地址」

上游返回的结果链接指向内网或本机地址，服务端拒绝去取。如果上游是你自己网络里的模型服务，把它的主机加到 `SSRF_ALLOW_HOSTS` 并重启。请先读[安全](security.zh-CN.md#ssrf-防护)。

## 存储

### 该用哪种存储

- **本地磁盘**（默认）：什么都不用配。适合一台机器、磁盘够用的情况。记得备份 `app_data` 数据卷。
- **S3 兼容的桶**（AWS S3、Cloudflare R2、阿里云 OSS、MinIO 等）：磁盘不够用、希望文件不随这台机器丢失，或者上游模型要按地址读取参考视频而实例没有公网地址时。

在「设置 → 存储」里配置。详见[存储](storage.zh-CN.md)。

### 桶需要设成公开的吗

不需要。默认的 `proxy` 分发下，桶保持私有：应用用自己的凭据去读，再通过 `/files/<key>` 把文件提供出来。不需要公共读，也不需要配 CORS。只有选了 `redirect` 分发、让浏览器直接从桶或它的 CDN 加载文件时，才需要一个公开域名。见[存储](storage.zh-CN.md#两种分发方式)。

注意：不管哪种方式，`/files/<key>` 本身都是公开的，见[安全](security.zh-CN.md#哪些是公开的)。

### 切换存储时，原来的文件会怎样

不会怎样：文件不会被移动，也不会被复制，没有迁移工具。新文件存到新的地方；之前的文件留在原处，只要那个地方还在，就照常从那里加载。不要删除本地目录（或 `app_data` 数据卷），也不要删除旧桶或吊销它的密钥。想把所有文件放到一处，可以自己复制。见[存储](storage.zh-CN.md#切换存储时会发生什么)。

### Cloudflare R2、阿里云 OSS、AWS S3 能用吗

它们都是 S3 兼容的，各自的配法见[存储](storage.zh-CN.md#各家服务的配法)；但在本项目里，只有 MinIO 对着真实服务跑过。请用「设置 → 存储」里的「测试连接」验证，并欢迎反馈结果。

### 以前用的是 `STORAGE_DRIVER=oss`，现在服务端启动不了

`oss` 驱动已经移除。阿里云 OSS 现在通过它的 S3 兼容接口使用，设 `STORAGE_DRIVER=s3`。要改名的变量见[存储](storage.zh-CN.md#从-storage_driveross-迁移)。

### 文件返回 503

这个文件哪里都没找到，而应用被配置成要去读的某个存储（当前使用的桶、更早的桶，或 `S3_*` 变量描述的桶）没问到：连不上、不认这把密钥，或者保存的密钥解不开。这种情况返回 `503`（`storage.unreachable`）而不是 `404`，因为文件很可能是存在的。这期间，本地磁盘上和当前使用的桶里的文件照常加载。「设置 → 存储」会显示是哪个桶，服务端日志里有一行 `[storage]`。如果那个桶已经彻底没了，把它从列表里去掉，找不到的文件就重新是 `404`。见[存储](storage.zh-CN.md#存储连不上的时候)。

### 改了 `SECRET_KEY` 之后上传失败

保存的密钥是用 `SECRET_KEY` 加密的。换了 Key，服务端仍能启动，但保存的 S3 密钥和所有服务商的 Key 都解不开了：正在使用桶的话，上传返回 `503`（`storage.secret_unreadable`），桶里的文件加载不出来，运行会提示重新填写 API Key。把原来的 `SECRET_KEY` 改回去，或者到「设置 → 存储」和「模型」页重新填写密钥。见[存储](storage.zh-CN.md#备份)。

## 运行

### 运行好像卡住了

- 长时间**排队中**：并发名额都占满了，或者你这个账号已经占到了单个账号的上限；在团队空间里，也可能是整个团队占到了团队的并发上限。超级管理员可以在「设置 → 运行限制」里调大「同时运行的任务数」「每个账号的并发上限」和「团队并发上限的默认值」；否则等一等。
- 长时间**运行中**：上游还没出结果。运行不会无限等下去：默认图片运行 10 分钟后判失败，视频运行 30 分钟（「设置 → 运行限制」）。对话请求 5 分钟后失败（`chatTimeoutSec`）。
- 运行中的节点上有「取消运行」按钮。排队中或进行中的运行也可以通过接口取消：`POST /api/runs/<id>/cancel`（见 [API](api.md#models-and-runs)）。运行的 id 就是 `GET /api/admin/usage/records` 返回的记录里的 `id`。
- 服务端重启后，排队中的运行和已经拿到上游任务号的运行会自己接着跑。时限从最初提交时算起，重启不会让它变长。服务端停止时正在发出请求的运行则会失败，见下面的「服务在提交这个任务时停止了…」。
- 如果经常超时，而上游最后其实出了结果，就把超时调大。如果超时发生在「下载结果」这一步，调大 `downloadTimeoutSec`（见[配置](configuration.zh-CN.md#管理设置)）。

失败原因在节点的任务详情里，也在「生成记录」页（那一行的「查看详情」，连同错误码）里。意料之外的问题，服务端日志里信息更多：`docker compose logs app`。

### 生成记录里的结果能一次下载多个吗

能。在「生成记录」页勾选要的记录（表头的勾一次选中这一页所有可下载的，翻页之后勾选还在），点「下载 ZIP」，得到一个压缩包：图片、视频运行的文件，加上每条对话的回复（`.txt`），按勾选的顺序编号。

- 一个压缩包最多 100 条记录、100 个文件；选中条上有文件数，超了会提示。超了就分几批下。
- 只有已成功、结果还在的运行能勾选。结果文件已经按保留期清理的，记录还在，但没有东西可下载。
- 哪个文件已经不在了，压缩包里会有一个 `…-failed.txt` 说明。下载本身中断了，不会留下半截的文件：再点一次「下载 ZIP」。
- 一条记录有几个文件时，它自己那一行的「下载」也是一个 ZIP。

### 生成记录里的「不计费」「成本未知」和「≈」是什么意思

- **不计费**：这次运行失败了或者被取消了。LoomCanvas 不把它算进花费（团队里也不计入每月上限）。上游对失败的调用收没收钱，以上游的账单为准。
- **成本未知**：运行成功了，但当时这个模型在「模型管理」里没有填价格。它单独计数，不会算成 0。填上价格之后，以后的运行才有成本；过去的记录不会重算。
- **≈ 金额**：还在排队或运行，这是提交时的预估。

顶上的「预估花费」= 已成功且有价格的运行，加上还在跑的运行占着的那一份。

### 「已有 500 个未完成的运行」

提示里的数字是碰到的那一个上限。一个账号排队中和进行中的运行最多 `userQueueLimit` 个（默认 200，超级管理员可以改，见[配置](configuration.zh-CN.md#管理设置)），整个实例最多 500 个。等一部分跑完，或者取消一部分。大批量的批量运行可能碰到这个上限。

### 「服务在提交这个任务时停止了…」

那次运行的请求已经发出、上游任务号还没拿回来的时候，服务端停了（重启、升级、崩溃、内存不足、被强制结束）。它不会被再次提交，因为上游可能已经建好任务并计费了。请到上游查一下记录，需要的话再运行一次节点。

在同一个请求里直接返回结果的服务商（OpenAI 的图片、Gemini），以及大语言模型节点和视频分析节点，从来没有任务号，所以这类运行只要在服务端停止时正在进行，就是这个结果。

### 点「运行全部」没反应

「运行全部」和「运行此分支」需要链路末端有一个成品节点。加一个成品节点，把结果连过去；或者用单个节点上的运行按钮。

## 编辑器

### 节点工具栏上少了几个按钮

编辑区太矮，放不下整条工具栏：窗口很矮、开着浏览器的开发者工具，或者编辑器嵌在别的页面里。按钮先变小一号，然后有几个收进「更多工具」：先收输出与工具、对话 / 分析，文本按钮最后收。什么都没丢：收起来的都列在「更多工具」里，「+」里照样是全部节点，编辑区变高之后它们自己回来。把工具栏拖到宽敞的地方，或者用把手旁边的开关换成横向，也管用。

### 小地图不见了

地方不够时它会让位，够了自己回来：编辑区不到大约 370px 高的时候；以及紧凑布局下，属性面板开着、窗口宽度又在 1000 到 1100px 左右的时候。收起属性面板（Esc），或者把窗口拉大。

### 生成队列的圆钮怎么放回右下角

点圆钮打开清单，点表头里的「复位」；圆钮被挪走之后才有这一项。把圆钮直接拖回右下角也一样。双击不会复位，只是把清单开了又关。节点工具栏从它的把手复位：点一下把手，选「复位」。

### 选中节点时画布自己动了一下

那是编辑器在腾地方。「结果优先」布局下输入条不会盖住节点的端口，节点四边都放不下它时，画布会平移到刚好放得下；紧凑布局下，选中的节点落在属性面板底下时也一样。变的只是视野：画布本身没有任何变化，也没有什么要撤销的。

### 用输入法打字时，按回车会不会运行节点

不会。输入法组字期间，回车是上屏，Esc 是取消组字，都不会运行节点，也不会收起输入条。字上屏之后，Ctrl+Enter 才是运行。选中节点后可以直接开始组字，不用先点进提示词框。

## 访问与启动

### 改了 SECRET_KEY 之后，保存的 API Key 不能用了

服务商的 Key 是用 `SECRET_KEY` 加密的。换了密钥就解不开，运行会失败并提示「无法解密该服务商的 API Key（SECRET_KEY 是否被改过？），请重新填写」。

- 旧的 `SECRET_KEY` 还在：改回去并重启，一切恢复。
- 找不回来了：打开「模型管理」页，每张服务商卡片上都写着「Key 读不出」；点卡片上的「重新填入 Key」，填好 API Key 保存。每个账号都要给自己的服务商做一遍（团队里由团长或管理员来做）。文件存在「设置 → 存储」保存的桶里时，超级管理员还要在那里重新填写它的 Secret Access Key，见[改了 `SECRET_KEY` 之后上传失败](#改了-secret_key-之后上传失败)。其他数据不受影响，也不会有人被退出登录：会话不依赖 `SECRET_KEY`。

### 超级管理员密码在哪

超级管理员账号是服务端第一次启动时创建的，不靠注册产生。用户名是 `admin`，除非当时设了 `ADMIN_USERNAME`。

- 第一次启动时设了 `ADMIN_PASSWORD`：密码就是它。
- 没设：服务端生成了一个，在启动日志里打印过一次，是一个以 `LoomCanvas created the super admin account.` 开头的框。用 Docker Compose 时执行 `docker compose logs app`，搜 `Password:`；不用 Docker 时它在当时运行 `npm start` 的终端里。用它登录后，系统会要求你先换成自己的密码。
- 找不到了（日志没了，或者改过密码又忘了）：用命令行重置，`docker compose exec app node src/cli/reset-password.js admin`，不用 Docker 时是 `node server/src/cli/reset-password.js admin`。见下一个问题。

`ADMIN_PASSWORD` 只在创建这个账号时读取，事后再设、再改都不起作用。

### 忘记密码了怎么办

LoomCanvas 不发邮件，所以没有重置链接。有两个办法：

- **找超级管理员。** 超级管理员在「设置 → 用户管理」里对你的账号点「重置密码」，拿到一个临时密码转给你。
- **你就是超级管理员，或者服务端是你在运行。** 用命令行重置；超级管理员自己的密码只能这样重置。服务端不用停：

  ```bash
  docker compose exec app node src/cli/reset-password.js <用户名或邮箱>
  ```

  不用 Docker 时，在仓库根目录执行：`node server/src/cli/reset-password.js <用户名或邮箱>`。

两种办法都会给出一个只显示一次的临时密码，并让这个账号在所有设备上退出登录。用它登录后，系统会马上要求你设置新密码，在这之前别的都用不了；在那之前，「设置 → 用户管理」里这个账号带着「待改密码」的标记，状态筛选里的「待改密码」能把这样的账号都列出来。详见[部署](deployment.zh-CN.md#忘记密码)。

### 超级管理员删除一个账号，会发生什么

「设置 → 用户管理 → ⋯ → 删除账号」，敲一遍用户名确认之后：

- 这个账号在所有设备上的登录立刻失效，以后也登录不了。
- 它**个人空间**里的东西全部永久删除：画布、素材、品牌包、模板、服务商配置、生成记录，连同文件。删除不会等一个慢的或者连不上的存储：账号当场删掉，页面提示文件还没有全部删完，剩下的在后台继续删（每 10 分钟重试一次，最多 30 天），不需要手工清理，见[存储](storage.zh-CN.md#存储连不上的时候)。
- **团队里的东西留给团队。**它会退出所在的每个团队；它在团队里做的画布、素材和记录属于团队，都留着，署名是它的名字加「账号已删除」。只有它自己看得到的团队画布交给团长，还在排队的运行被取消，它建的邀请链接作废。
- 还是某个团队**团长**的账号删不了：先把团队交出去（在团队设置里转让；账号已经停用的话，在「设置 → 团队」里指定新团长），或者先删除那个团队。

### 怎么让不再用的设备退出登录

「设置 → 账号与安全 → 登录会话」列着你的账号现在登录着的每一个浏览器，当前这个排在最前。「下线」结束其中一个；「下线其他全部会话」把除了你正在用的这个之外的都结束掉。被下线的浏览器下一次和服务端通信时会回到登录页。修改密码也会让其他会话全部下线。

### 「尝试次数过多，请稍后再试」

触发了限流：

| 限制 | 值 |
| --- | --- |
| 同一个客户端地址对同一个账号的登录尝试 | 每 10 分钟 10 次 |
| 同一个客户端地址的登录尝试，不论试的是哪些账号 | 每 10 分钟 30 次 |
| 针对同一个账号的登录尝试，所有地址合计 | 每 10 分钟 100 次 |
| 登录尝试合计 | 每 10 分钟 3000 次 |
| 同一个客户端地址的注册尝试 | 每小时 20 次 |
| 修改用户名或邮箱 | 每个账号每小时 20 次 |

响应（HTTP 429，错误码 `auth.too_many_attempts`）里写着要等多久：响应体里的 `data.retryAfterSeconds` 和响应头 `Retry-After`。等这么久，或者重启服务端清空计数。修改密码时输错当前密码，也算一次针对这个账号的登录尝试。

别人拿你的用户名乱猜，不会把你锁在外面。后两条登录限制对你这个账号的「熟悉地址」不生效：最近 30 天里你从那里成功登录过的地址，或者你现在还登录着的地址。只有从一个你从没用过的地址登录时，才可能要在这种猜测进行期间等一等。见[安全](security.zh-CN.md#限流)。

如果在反向代理后面所有人都碰到这个提示，说明服务端把所有访问者都当成了代理。设置 `TRUST_PROXY=1`（前面代理的层数）；`TRUST_PROXY=true` 不被接受。

### 怎么关闭注册

注册默认是开放的，注册出来的只会是普通账号。关掉它有三个办法：

- 第一次启动之前，在 `.env` 里设 `REGISTRATION_OPEN=false`。这个变量只给这项设置一个初始值；设置一旦保存过（由这个变量、设置页或接口保存），就不再理会它。
- 超级管理员在「设置 → 站点」里把「开放注册」关掉。
- 或者超级管理员发一个请求：

```bash
curl -X PUT http://localhost:3000/api/admin/site \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"registrationOpen": false}'
```

已有的账号照常登录。新的注册会被拒绝，提示「本站已关闭注册」。要再放一个人进来，就先打开，等他注册完再关上。陌生人能访问到的实例，请一直关着，见[安全](security.zh-CN.md#账号)。

### 升级到有账号的版本后，原来的数据会怎样

什么都不会丢，也不需要手动迁移。新版本第一次启动时，服务端创建超级管理员，**并把已有的全部数据交给它**：画布、分享链接（原来的链接照常可用）、资产、品牌包、服务商和它们的 Key、模型和价格、用量记录，以及你自己做的模板。

所以第一次启动之前，先在 `.env` 里设好 `ADMIN_PASSWORD`（或者启动后从日志里读出生成的密码），`SECRET_KEY` 不要改，并把 `ACCESS_PASSWORD` 删掉。然后用超级管理员账号登录，数据都在。注册出来的账号是空的，看不到任何旧数据。完整的清单见[部署](deployment.zh-CN.md#从没有账号的版本升级)。

### 升级之后画布好像被重新排过

改版之后生成节点高了很多，按旧尺寸摆的节点可能会叠在一起。所以最后一次保存还在旧版本的画布，第一次在编辑器里打开时会自动整理一次，而且只在节点按新尺寸确实互相重叠时才整理。排法和底部工具条的「自动整理」是同一套。会有一条提示告诉你；按 Ctrl+Z 可以回到原来的位置。每张画布只发生一次，用当前版本保存过的画布不会被动。内置的两个模板也按新尺寸重新排过。画布文档现在是 `schemaVersion` 3；旧的在启动时或读取时自动迁移，不需要手动做什么。

### 有浅色主题吗？

有。默认是深色；顶栏上的太阳 / 月亮图标（落地页、登录页、分享页的页头和「页面不存在」那一屏也有；手机上落地页的在菜单里）可以在「深色 / 浅色 / 跟随系统」之间切换，「设置 → 外观」里是同一个选择，带预览图。选择跟着账号走，浏览器也会记住，所以登录页和打开时的首帧用的也是它。在一台主题不一样的浏览器上登录不会闪一下：应用打开的第一帧就是你账号的主题。没有全站的「默认主题」设置；早期版本存下来的值不再使用。

画布的底色留在默认档时，跟着看的人的主题走。自己选的底色在两套主题下都原样保留，连线、组的虚线框、图案和小地图的外框会跟着这个底色的明暗调整。

### 服务端一启动就退出

看日志的最后几行（`docker compose logs app`）。常见原因：

| 信息里包含 | 原因 |
| --- | --- |
| `SECRET_KEY is required` | 没设，或不足 16 位。 |
| `must be an integer between` / `must be one of` | 某个环境变量的值不合法，信息里会指出是哪个。 |
| `TRUST_PROXY must be …` | `TRUST_PROXY` 既不是代理层数（1 到 10），也不是地址列表。`true` 和主机名都会被拒绝。 |
| `ADMIN_PASSWORD must be 8 to 128 characters long` | 正要创建超级管理员，而 `ADMIN_PASSWORD` 太短或太长。换一个长一些的，或者删掉它，让服务端生成。 |
| `ADMIN_USERNAME … is already the name of another account` / `ADMIN_EMAIL is already the email of another account` | 还没有超级管理员，而这个用户名或邮箱已经被某个普通账号用了。换一个值。 |
| `REGISTRATION_OPEN must be true or false` | 这个变量写成了别的值。 |
| `已不再支持 STORAGE_DRIVER=oss` | `oss` 驱动已经移除。请改用 `STORAGE_DRIVER=s3`，Endpoint 填 OSS 的 S3 兼容地址。见[存储](storage.zh-CN.md#从-storage_driveross-迁移)。 |
| `STORAGE_DRIVER=s3 requires …` | `S3_BUCKET`、`S3_ACCESS_KEY_ID` 或 `S3_SECRET_ACCESS_KEY` 为空。 |
| `The S3_* storage settings are not valid` | 某个 `S3_*` 变量的值不被接受（Endpoint 带了路径、桶名不合法、设了 `S3_DELIVERY=redirect` 却没有 `S3_PUBLIC_BASE_URL` 等）。见[存储](storage.zh-CN.md#环境变量一览)。 |
| `WEB_DIST is set to … but there is no index.html` | 前端没有构建，或路径不对。 |
| `BILLING_HOOK could not be loaded` | 钩子文件不存在，或加载时抛错。 |
| MongoDB 连接错误 | 按 `MONGODB_URI` 连不上数据库。 |

### 磁盘越用越多

生成的文件默认永久保留。可以：

- 在「设置 → 存储」里把新文件改存到桶里。已经在磁盘上的文件留在原处，见[存储](storage.zh-CN.md#切换存储时会发生什么)。
- 在「设置 → 运行限制」里设置「结果保留天数」。早于这个天数的运行，结果文件会被删除；还显示着它们的画布会出现破图。
- 用量记录本身很小，也可以在「生成记录」页用「清理记录」删除旧的。它只删记录，不删文件。
- 删除画布或资产不会删除它们的文件。

## 团队

团队怎么用见[使用指南的「团队」一章](user-guide.zh-CN.md#团队)，准确的规则见[接口文档](api.zh-CN.md#空间与团队)。

### 成员看得到团队的 API Key 吗

看不到。成员在团队的「模型管理」页只看到服务商的名称、是否启用、「已由团队配置」，以及模型和价格；Key、Key 的末几位和接口地址都不显示，也没有任何接口把它们返回给成员。团长和管理员看到的和个人空间一样：是否已设置和末四位，同样没有 Key 本身。

所以成员离开团队不需要换 Key。离开的是一位填写过 Key 的管理员时，他知道那些 Key：移除他的时候界面会列出涉及的服务商，请到上游把这些 Key 换掉。

### 在团队里运行，用的是谁的 Key

团队的。团队空间里只有团队自己的服务商，成员个人的 Key 不会用在团队里；团队的 Key 也不会用在任何人的个人空间。想用自己的 Key，在空间切换器里切回个人空间。

### 两个人同时打开同一张画布会怎样

先打开的人可以编辑，后打开的人是只读，顶上写着「某某 正在编辑，你现在是只读」。只读也能好好地看：点开图片和视频看大图、播放视频、选中和复制文字与提示词、切换查看历史版本、下载结果；不能修改，也不能运行。只读的人可以「复制一份」，有这张画布编辑权的还可以「接管编辑」。接管的人马上就能编辑；对方的页面要到下一次自动续期或保存时才变成只读（约 12 秒内），这之前还没保存的改动留在对方的页面上，可以另存为副本。没有多人同时编辑，也没有合并。先打开的人离开（或者直接关掉标签页）之后，后一个人大约 5 秒内会看到「开始编辑」，不用刷新页面。

**一个人开两个标签页**也一样：锁属于标签页，第二个标签页是只读的（「你在另一个标签页（或另一台设备）打开了这张画布」），点「在这里编辑」把编辑挪过来。

**改名**不算编辑：有编辑权的人可以在别人正在编辑时，从列表或编辑器的标题上给画布改名。对方的标题几秒内跟着变，他做的任何事都不会因此被拒绝。

万一两边都改了（比如编辑锁过期了，或者被接管时还有没保存的改动），后保存的那一方不会盖掉对方：保存被拒绝，弹出「这张画布已被别人修改」，可以把自己的版本另存为副本。见[轮流编辑](user-guide.zh-CN.md#轮流编辑)。

### 为什么我不能创建团队

创建团队要超级管理员授权。空间切换器里显示的是「申请创建团队」时，说明你的账号还没有授权：提交一条申请，或者直接找超级管理员（「设置 → 用户管理」里那一行的「允许创建团队」）。已有授权但仍然不能创建，是到了数量上限：你创建的或担任团长的团队都算，已解散、还没被永久删除的也算；上限由超级管理员在「设置 → 团队」里设置，默认 3 个。

加入别人的团队不需要授权，有邀请链接就行。

### 运行被拒绝了，提示本月上限已用完，或者模型没有价格

团队设了每月上限。说明就出现在你点「运行」的地方，并且一直留着；它写明是哪一项上限、具体数字、什么时候重新开始计数（按团队的时区）、该找谁。一共六种：

| 提示说的是 | 发生了什么 | 怎么办 |
| --- | --- | --- |
| 你本月的运行次数已用完 | 你自己的次数上限用完了。 | 等到提示里的日期，或者请团长（提示里有名字）在「团队 → 成员 → 调整上限」里提高。 |
| 团队本月的运行次数已用完 | 团队的次数上限用完了，哪怕你自己的还有余量。 | 等，或者请团长在「团队 → 团队设置 → 额度」里提高。 |
| 这次运行超出了你本月的金额上限 | 这次运行的预估金额比你剩下的额度多。提示里两个数都有。 | 换便宜一点的模型或少出几张，也许还放得下；否则同上。 |
| 这次运行超出了团队本月的金额上限 | 同上，说的是团队的。 | 同上。 |
| 「…」还没有填价格，不能运行 | 团队设了金额上限，而这个模型没有价格，成本算不进上限。 | 请团长或管理员（提示里都有名字）在「模型管理」里给它填价格，或者由团长关掉「没填价格的模型禁止运行」。等到下个月没有用。 |
| 「…」的价格是 USD，金额上限按 CNY 计 | 模型有价格，但不是团队上限用的那种货币。 | 请团长或管理员给它填一个团队货币的价格。 |

**什么算「已用」？** 已成功的运行，加上进行中的（排队、运行、保存结果）。失败和取消的不计入，占着的名额会退回。显示上限的页面都把它们单独列出来。

**对话运行几乎不花钱，却被拒绝了。** 按 token 计价的对话模型要跑完才知道成本，所以运行前先按最长回答占一笔预留，提示里写着是多少；跑完之后换成真实成本。剩下的额度放不下这笔预留时，运行在提交时就被拒绝，这样上限才不会被悄悄超出。

已经在排队或运行的任务不受影响。上限只管团队空间，不影响你的个人空间。金额是按团队填的价格算的预估，不是上游的账单。

### 运行显示「排队时被取消」

没有人点过取消：这次运行还在排队时，发起它的人退出或被移出了团队，或者他的账号被超级管理员停用了，或者团队被解散、停用了。记录里写着是哪一种。已经开始的运行会跑完；被取消的不计入每月上限。

### 我退出团队之后，我做的东西会怎样

留在团队。你建的画布、传的素材、跑出来的结果都属于团队，不会跟着你走，也不会被删掉；你设为「仅自己」的画布转给团长。你排队中的运行被取消，已经开始的会跑完。被移出团队时结果一样。

想带走一份，在退出之前把画布或资产复制到个人空间（团长可以在团队设置里关掉这一项）。你的个人空间不受团队的任何影响。

### 素材都移走了，分组为什么还在

分组是独立存在的：里面的素材移走或删掉之后它还在，只是空了。不再用的分组到「素材库 → 分组」里手动删除；只有空分组能删。里面还有素材时删除会被拒绝并说明还有几个，这时可以先把素材移走，或者选「解散分组，素材保留」（分组消失，素材保留、不在任何分组里；团队里需要团长或管理员）。团队里成员只能删自己建的空分组。

### 「复制到…」里有的空间是灰的

弹窗列出你所在的每一个空间，去不了的灰着并写明原因：团长关闭了「允许成员把团队画布和资产复制到个人空间」（团长自己不受限）；那个团队被超级管理员停用了，或者已经解散；那个空间里这一类素材已经到了 5000 个的上限；或者它就是你现在所在的空间。

### 服务商卡片上的「未测试」「上次测试失败」是什么意思

是最近一次「测试连接」的结果，由服务端记着，团长和管理员（以及个人空间里的你自己）看得到。「未测试」表示还没测过，或者测过之后换了 Key 或接口地址——上一次的结果已经不作数。「上次测试失败」的原因写在卡片下方。团队成员看不到测试结果，只看到「可用」或「不可用」。卡片上的「维护人」是最后改动这个服务商的人。

### 团队动态里的人名后面为什么带「已离开团队」「账号已删除」

动态里显示的是这个人现在的样子。他已经不在团队里了，但名字和他做过的事都留着；画布、素材、生成记录、邀请链接、模板上的名字也一样。很早以前离开、名字没有留下来的人，显示为「前成员」或「已删除的账号」。

### 站点关闭了注册，邀请链接还能用来注册吗

不能。邀请链接只能让一个已有的账号加入团队。站点关闭注册时，加入页会说明本站目前不接受新账号，不会提供注册入口。要让一个没有账号的人加入，超级管理员得先在「设置 → 站点」里把注册打开，等对方注册完再关上。

### 超级管理员看得到团队里的什么

只有数字。「设置 → 团队」里列出每个团队的名称、团长、成员数、画布数、运行数、并发上限和状态。超级管理员可以调整团队的上限、停用和恢复团队、恢复已解散的团队、在团长账号不可用时指定新团长、永久删除已关闭的团队；但进不了自己不是成员的团队，看不到其中的画布、素材、提示词、生成记录和 Key。

### 改服务商的接口地址时，为什么要我重新填 Key

已保存的 Key 只会发往保存时的那个地址。否则，能编辑服务商的人可以把地址改到自己的服务器上，把别人填的 Key 骗走。所以在已经存有 Key 的服务商上改「接口地址」，表单会要求重新填写 API Key；个人空间和团队都一样。

存储设置同理：在「设置 → 存储」里改了服务地址或 Access Key ID，需要重新填写 Secret Access Key。

## 适用范围

### 几个人能各用各的账号共用一个实例吗

能。每个人自己注册一个账号，每个账号有自己的个人空间：自己的画布、文件、服务商和 API Key、模型、价格和用量。超级管理员（服务端自己创建的那一个账号）负责管理站点和账号列表，但看不到别人做的东西。

要几个人共用同一套画布、素材和 Key，建一个[团队](user-guide.zh-CN.md#团队)：成员轮流编辑团队的画布，用团队的 Key 运行，团长可以按月限制用量。团队不是实时协作，同一张画布同一时间只有一个人能改。只想把一张画布交给别人，也可以发布一条分享链接，让对方复制一份；模型标识是按空间的，对方的空间里得有一个标识相同的服务商，复制出来的画布才找得到模型。

账号之间、团队之间靠接口隔离，不是各跑各的进程、各用各的数据库。把实例开放给不认识的人之前，请先看[安全](security.zh-CN.md#账号)。

### 我的上游不是这三家服务商

如果它是一个代理或中转，使用的接口与 OpenAI 或 Gemini 的官方接口完全相同，就添加 OpenAI 或 Google Gemini 服务商，在「高级」里修改「接口地址」；它的模型不在列表里的话，作为自定义模型添加。LoomCanvas 不为第三方的私有格式做适配。别的服务商需要写一个服务商模块加一份模型清单：[编写服务商模块](writing-a-provider.zh-CN.md)。

### 这些服务商对着真实服务测过吗

内置的高瑞模型已经对着真实服务运行过；OpenAI 和 Google Gemini 按官方文档接入，项目还没有实际运行过。S3 存储驱动是对着 MinIO 测试的；AWS S3、Cloudflare R2、阿里云 OSS 没有对着真实服务跑过（见[存储](storage.zh-CN.md#测试情况)）。请在自己的环境里确认，并欢迎反馈结果。
