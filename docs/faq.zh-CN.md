# 常见问题

[English](faq.md)

自己部署实例的人常会遇到的问题。画布使用上的问题，应用内的教程（编辑器里「更多 ⋯ → 使用教程」）里有单独的常见问题，也可以看[使用指南](user-guide.zh-CN.md)。

## 模型与成本

### 节点上显示「成本未知」

这个模型没有与当前参数对得上的价格。LoomCanvas 不自带任何价格：它无从知道你的上游向你收多少钱。

1. 打开「模型管理」页，选中服务商，找到模型，点「设置价格」。
2. 填上你实际支付的单价。价格随分辨率或时长变化的，在「价格随什么变化」里选对应的项，每个档位填一行。

价格表里没有当前分辨率或时长对应的那一行，同样是「成本未知」。按 token 计价的对话模型在运行前显示未知，运行后如果上游返回了 token 用量才有成本。没有价格的模型照样可以运行。详见[服务商](providers.zh-CN.md#价格)。

### 模型下拉是空的，或者提示「还没有可用的模型」

按这个顺序检查：

1. 「模型管理」页：有没有添加服务商，卡片上是否显示已启用、Key 已设置？点一下卡片上的「测试连接」。
2. 还是这一页，选中那个服务商：它的模型开关是否打开？
3. 节点类型对不对？视频编辑节点只列出视频编辑模型。OpenAI 和 Gemini 这两家服务商完全不提供视频模型。
4. 大语言模型节点：列出所有已启用的对话模型。高瑞服务商有五个（三个纯文本，两个可读图片）；服务商列表里没有的对话模型，可以在「模型管理」页作为自定义模型添加。选了纯文本模型时，节点的图片输入口会变灰，已连接的图片不会发送。
5. 视频分析节点：只列出能输入视频的对话模型。目前是高瑞服务商下的 `gemini-3.5-flash-c`，以及高瑞服务商下的自定义对话模型。OpenAI 和 Gemini 的对话模型不会出现在这里。

模型列表不取决于上游连不连得上：它就是服务商自带的模型列表加上你的自定义模型。

### 需要的模型没出现，或者列出了不该有的

每家服务商支持哪些模型是一份固定的列表，随 LoomCanvas 一起发布。不会去读上游的模型列表，也不会根据模型的名字去猜。

- 缺了：打开「模型管理」页，选中那个服务商，点「添加自定义模型」。模型名按上游要求的原样填写，并选择类型（图片或对话）。不能添加自定义视频模型。
- 多了：在「模型管理」页把它的开关关掉。
- 从上一个版本升级之后，自定义模型的类型可能不对，或者用过的模型没有带过来，见[从上一个版本升级](providers.zh-CN.md#从上一个版本升级)。

### 重新运行节点会再计一次费吗

会。每次运行都会向上游提交一个新任务。对已经有结果的节点重新运行前，画布会先让你确认。之前的结果留在节点的历史版本里。

### 这里的金额和真实账单一致吗

不一定。金额是按你填的价格、在提交运行时算出来的（对话模型则按返回的 token 用量算）。以上游的账单为准。失败的运行在这里不计花费，即使上游已经为它收了钱。

## 素材

### 运行失败，提示「…需要公网可访问的地址…」

有些输入只能以地址的形式交给上游：高瑞图片模型的参考图（图生图）、视频编辑的原视频、部分视频模型的参考图、对话里的视频。上游必须能从公网下载这个地址。

两种解决办法选一个：

- 把 `PUBLIC_URL` 设成实例的公网地址（例如 `https://canvas.example.com`），并确认它真的能从公网访问；或者
- 把文件存到公网上能访问到的 S3 兼容的桶里（「设置 → 存储」）。桶里的文件交给上游时用的是有效期一小时的预签名地址，所以既不需要 `PUBLIC_URL`，桶也不用公开。

用 `PUBLIC_URL` 这个办法时，画布上已有的文件不用重新上传：它们的地址是站内相对地址，交给上游时才拼上 `PUBLIC_URL`。改用桶并不会搬走已经在本地磁盘上的文件；这些文件仍然需要 `PUBLIC_URL`，或者重新上传一次。`localhost` 和内网地址永远不算公网地址。见[服务商](providers.zh-CN.md#素材怎么送到上游)和[存储](storage.zh-CN.md#给上游模型的参考素材)。

### 从另一台电脑打开，图片全是破图

不管文件在本地磁盘上还是在桶里，都是按站内相对地址（`/files/<key>`）保存的，从哪个地址打开应用就从哪个地址加载。所以当前版本存下的文件不应该出现这个问题，不管 `PUBLIC_URL` 是什么。

早期版本保存的画布仍可能出现：那时存的是绝对地址，例如 `http://localhost:3000/files/…`，另一台电脑的浏览器访问不到。把这些文件重新上传，或者重新运行节点。见[部署](deployment.zh-CN.md#public_url)。

### 缩略图是怎么回事，为什么有的没有

- 节点里显示的是一张小的 WebP 缩略图（最长边 512 像素），不是原图；查看大图和下载用的始终是原图。
- 缩略图在上传文件或转存结果时生成。缺的那张会在第一次被请求时现做一份并保留。本地磁盘和桶都一样；缩略图和它的原图存在同一处。
- 只有 PNG、JPEG、WebP、BMP、AVIF 图片有缩略图。视频、GIF、HEIC 没有，直接显示原文件。
- 很小的上传图片（最长边不超过 512 像素）自己就是自己的缩略图。
- 外部地址的图片，以及早期版本保存的画布里用桶的绝对地址引用的图片，推不出缩略图地址，直接显示原图。这只是慢一些，不是坏了。

### 上传失败，或提示文件太大

有两道限制，取较小的：

| 限制 | 默认 | 在哪里 |
| --- | --- | --- |
| 服务端，每个文件 | 50 MB | `MAX_UPLOAD_MB`。画布从服务端读到这个值，超过的文件在上传前就会被拦下。 |
| 反向代理 | 各不相同（nginx 不配置时是 1 MB） | `client_max_body_size` 或类似配置 |

如果收到 `413`，而且看起来不是 LoomCanvas 的提示，那就是代理返回的。只接受图片和视频文件，按内容判断。

### 结果下载失败：「不允许访问内网地址」

上游返回的结果链接指向内网或本机地址，服务端拒绝去取。如果上游是你自己网络里的模型服务，把它的主机加到 `SSRF_ALLOW_HOSTS` 并重启。请先读[安全](security.zh-CN.md#ssrf-防护)。

## 存储

### 该用哪种存储

- **本地磁盘**（默认）：什么都不用配。适合一台机器、磁盘够用的情况。记得备份 `app_data` 数据卷。
- **S3 兼容的桶**（AWS S3、Cloudflare R2、阿里云 OSS、MinIO 等）：磁盘不够用、希望文件不随这台机器丢失，或者上游模型要按地址读取参考视频而实例没有公网地址时。

在「设置 → 存储」里配置。详见[存储](storage.zh-CN.md)。

### 桶需要设成公开的吗

不需要。默认的 `proxy` 分发下，桶保持私有：应用用自己的凭据去读，再通过 `/files/<key>` 把文件提供出来。不需要公共读，也不需要配 CORS。只有选了 `redirect` 分发、让浏览器直接从桶或它的 CDN 加载文件时，才需要一个公开域名。见[存储](storage.zh-CN.md#两种分发方式)。

注意：不管哪种方式，`/files/<key>` 本身都是公开的，见[安全](security.zh-CN.md#哪些是公开的)。

### 切换存储时，原来的文件会怎样

不会怎样：文件不会被移动，也不会被复制，没有迁移工具。新文件存到新的地方；之前的文件留在原处，只要那个地方还在，就照常从那里加载。不要删除本地目录（或 `app_data` 数据卷），也不要删除旧桶或吊销它的密钥。想把所有文件放到一处，可以自己复制。见[存储](storage.zh-CN.md#切换存储时会发生什么)。

### Cloudflare R2、阿里云 OSS、AWS S3 能用吗

它们都是 S3 兼容的，各自的配法见[存储](storage.zh-CN.md#各家服务的配法)；但在本项目里，只有 MinIO 对着真实服务跑过。请用「设置 → 存储」里的「测试连接」验证，并欢迎反馈结果。

### 以前用的是 `STORAGE_DRIVER=oss`，现在服务端启动不了

`oss` 驱动已经移除。阿里云 OSS 现在通过它的 S3 兼容接口使用，设 `STORAGE_DRIVER=s3`。要改名的变量见[存储](storage.zh-CN.md#从-storage_driveross-迁移)。

### 文件返回 502

应用被配置成要去读的某个存储服务（当前使用的桶，或更早的桶）连不上，或者不认这把密钥。这种情况返回 `502` 而不是 `404`，因为文件很可能是存在的。到「设置 → 存储」里做一次连接测试，并看服务端日志里以 `[files]` 开头的行。

## 运行

### 运行好像卡住了

- 长时间**排队中**：并发名额都占满了，或者你这个账号已经占到了单个账号的上限。所有者可以在「设置 → 运行限制」里调大「同时运行的任务数」和「每个账号的并发上限」；否则等一等。
- 长时间**运行中**：上游还没出结果。运行不会无限等下去：默认图片运行 10 分钟后判失败，视频运行 30 分钟（「设置 → 运行限制」）。对话请求 5 分钟后失败（`chatTimeoutSec`）。
- 运行中的节点上有「取消运行」按钮。排队中或进行中的运行也可以通过接口取消：`POST /api/runs/<id>/cancel`（见 [API](api.md#models-and-runs)）。运行的 id 就是 `GET /api/admin/usage/records` 返回的记录里的 `id`。
- 服务端重启后，排队中的运行和已经拿到上游任务号的运行会自己接着跑。时限从最初提交时算起，重启不会让它变长。服务端停止时正在发出请求的运行则会失败，见下面的「服务在提交这个任务时停止了…」。
- 如果经常超时，而上游最后其实出了结果，就把超时调大。如果超时发生在「下载结果」这一步，调大 `downloadTimeoutSec`（见[配置](configuration.zh-CN.md#管理设置)）。

失败原因在节点的任务详情里，也在「生成记录」页（那一行的「查看详情」）里。意料之外的问题，服务端日志里信息更多：`docker compose logs app`。

### 「已有 500 个未完成的运行」

提示里的数字是碰到的那一个上限。一个账号排队中和进行中的运行最多 `userQueueLimit` 个（默认 200，所有者可以改，见[配置](configuration.zh-CN.md#管理设置)），整个实例最多 500 个。等一部分跑完，或者取消一部分。大批量的批量运行可能碰到这个上限。

### 「服务在提交这个任务时停止了…」

那次运行的请求已经发出、上游任务号还没拿回来的时候，服务端停了（重启、升级、崩溃、内存不足、被强制结束）。它不会被再次提交，因为上游可能已经建好任务并计费了。请到上游查一下记录，需要的话再运行一次节点。

在同一个请求里直接返回结果的服务商（OpenAI 的图片、Gemini），以及大语言模型节点和视频分析节点，从来没有任务号，所以这类运行只要在服务端停止时正在进行，就是这个结果。

### 点「运行全部」没反应

「运行全部」和「运行此分支」需要链路末端有一个成品节点。加一个成品节点，把结果连过去；或者用单个节点上的运行按钮。

## 访问与启动

### 改了 SECRET_KEY 之后，保存的 API Key 不能用了

服务商的 Key 是用 `SECRET_KEY` 加密的。换了密钥就解不开，运行会失败并提示「无法解密该服务商的 API Key（SECRET_KEY 是否被改过？），请重新填写」。

- 旧的 `SECRET_KEY` 还在：改回去并重启，一切恢复。
- 找不回来了：打开「模型管理」页，逐个点服务商卡片上的「编辑」，重新填写 API Key。每个账号都要给自己的服务商做一遍。其他数据不受影响，也不会有人被退出登录：会话不依赖 `SECRET_KEY`。

### 忘记密码了怎么办

LoomCanvas 不发邮件，所以没有重置链接。有两个办法：

- **找所有者。** 所有者在「设置 → 用户管理」里对你的账号点「重置密码」，拿到一个临时密码转给你。
- **你就是所有者，或者服务端是你在运行。** 用命令行重置，服务端不用停：

  ```bash
  docker compose exec app node src/cli/reset-password.js <用户名或邮箱>
  ```

  不用 Docker 时，在仓库根目录执行：`node server/src/cli/reset-password.js <用户名或邮箱>`。

两种办法都会给出一个只显示一次的临时密码，并让这个账号在所有设备上退出登录。用它登录，再到「设置 → 账号与安全」里改成新密码。详见[部署](deployment.zh-CN.md#忘记密码)。

### 「尝试次数过多，请稍后再试」

触发了限流：

| 限制 | 值 |
| --- | --- |
| 同一个客户端地址对同一个账号的登录尝试 | 每 10 分钟 10 次 |
| 同一个客户端地址的登录尝试，不论试的是哪些账号 | 每 10 分钟 30 次 |
| 针对同一个账号的登录尝试，所有地址合计 | 每 10 分钟 100 次 |
| 登录尝试合计 | 每 10 分钟 3000 次 |
| 同一个客户端地址的注册尝试 | 每小时 20 次 |
| 修改用户名或邮箱 | 每个账号每小时 20 次 |

响应（HTTP 429，错误码 `auth.too_many_attempts`）里写着要等多久：响应体里的 `data.retryAfterSeconds` 和响应头 `Retry-After`。等这么久，或者重启服务端清空计数。修改密码时输错当前密码，也算一次针对这个账号的登录尝试。

别人拿你的用户名乱猜，不会把你锁在外面。后两条登录限制对你这个账号的「熟悉地址」不生效：最近 30 天里你从那里成功登录过的地址，或者你现在还登录着的地址。只有从一个你从没用过的地址登录时，才可能要在这种猜测进行期间等一等。见[安全](security.zh-CN.md#限流)。

如果在反向代理后面所有人都碰到这个提示，说明服务端把所有访问者都当成了代理。设置 `TRUST_PROXY=1`（前面代理的层数）；`TRUST_PROXY=true` 不被接受。

### 怎么关闭注册

注册默认是开放的，第一个账号注册之后也一样。所有者可以在「设置 → 站点」里把「开放注册」关掉，或者发一个请求：

```bash
curl -X PUT http://localhost:3000/api/admin/site \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"registrationOpen": false}'
```

已有的账号照常登录。新的注册会被拒绝，提示「本站已关闭注册」。要再放一个人进来，就先打开，等他注册完再关上。陌生人能访问到的实例，请一直关着，见[安全](security.zh-CN.md#账号)。

### 升级到有账号的版本后，原来的数据会怎样

什么都不会丢，也不需要手动迁移。在有人注册之前，数据原样不动；**第一个注册的账号成为所有者，并接手全部数据**：画布、分享链接（原来的链接照常可用）、资产、品牌包、服务商和它们的 Key、模型和价格、用量记录，以及你自己做的模板。

所以升级之后要马上打开实例注册，赶在别人能访问到之前。`SECRET_KEY` 不要改，并把 `ACCESS_PASSWORD` 从 `.env` 里删掉。之后注册的账号是空的，看不到任何旧数据。完整的清单见[部署](deployment.zh-CN.md#从没有账号的版本升级)。

### 升级之后画布好像被重新排过

改版之后生成节点高了很多，按旧尺寸摆的节点可能会叠在一起。所以最后一次保存还在旧版本的画布，第一次在编辑器里打开时会自动整理一次，而且只在节点按新尺寸确实互相重叠时才整理。排法和底部工具条的「自动整理」是同一套。会有一条提示告诉你；按 Ctrl+Z 可以回到原来的位置。每张画布只发生一次，用当前版本保存过的画布不会被动。内置的两个模板也按新尺寸重新排过。画布文档现在是 `schemaVersion` 2；旧的在读取时自动迁移，不需要手动做什么。

### 以前有浅色主题，现在没有了

界面现在只有一套深色主题。主题切换按钮和站点设置里的「默认主题」都没有了；早期版本存下来的值不再使用。

### 服务端一启动就退出

看日志的最后几行（`docker compose logs app`）。常见原因：

| 信息里包含 | 原因 |
| --- | --- |
| `SECRET_KEY is required` | 没设，或不足 16 位。 |
| `must be an integer between` / `must be one of` | 某个环境变量的值不合法，信息里会指出是哪个。 |
| `TRUST_PROXY must be …` | `TRUST_PROXY` 既不是代理层数（1 到 10），也不是地址列表。`true` 和主机名都会被拒绝。 |
| `已不再支持 STORAGE_DRIVER=oss` | `oss` 驱动已经移除。请改用 `STORAGE_DRIVER=s3`，Endpoint 填 OSS 的 S3 兼容地址。见[存储](storage.zh-CN.md#从-storage_driveross-迁移)。 |
| `STORAGE_DRIVER=s3 requires …` | `S3_BUCKET`、`S3_ACCESS_KEY_ID` 或 `S3_SECRET_ACCESS_KEY` 为空。 |
| `The S3_* storage settings are not valid` | 某个 `S3_*` 变量的值不被接受（Endpoint 带了路径、桶名不合法、设了 `S3_DELIVERY=redirect` 却没有 `S3_PUBLIC_BASE_URL` 等）。见[存储](storage.zh-CN.md#环境变量一览)。 |
| `WEB_DIST is set to … but there is no index.html` | 前端没有构建，或路径不对。 |
| `BILLING_HOOK could not be loaded` | 钩子文件不存在，或加载时抛错。 |
| MongoDB 连接错误 | 按 `MONGODB_URI` 连不上数据库。 |

### 磁盘越用越多

生成的文件默认永久保留。可以：

- 在「设置 → 存储」里把新文件改存到桶里。已经在磁盘上的文件留在原处，见[存储](storage.zh-CN.md#切换存储时会发生什么)。
- 在「设置 → 运行限制」里设置「结果保留天数」。早于这个天数的运行，结果文件会被删除；还显示着它们的画布会出现破图。
- 用量记录本身很小，也可以在「生成记录」页用「清理记录」删除旧的。它只删记录，不删文件。
- 删除画布或资产不会删除它们的文件。

## 适用范围

### 几个人能各用各的账号共用一个实例吗

能。每个人自己注册一个账号，每个账号有自己的画布、文件、服务商和 API Key、模型、价格和用量。第一个账号是所有者，负责管理站点和账号列表，但看不到别人做的东西。

没有团队，也没有共享空间：两个账号不能编辑同一张画布。想把画布交给别人，发布一条分享链接，让对方复制一份。要注意模型标识是按账号的，对方名下得有一个标识相同的服务商，复制出来的画布才找得到模型。

账号之间靠接口隔离，不是各跑各的进程、各用各的数据库。把实例开放给不认识的人之前，请先看[安全](security.zh-CN.md#账号)。

### 我的上游不是这三家服务商

如果它是一个代理或中转，使用的接口与 OpenAI 或 Gemini 的官方接口完全相同，就添加 OpenAI 或 Google Gemini 服务商，在「高级」里修改「接口地址」；它的模型不在列表里的话，作为自定义模型添加。LoomCanvas 不为第三方的私有格式做适配。别的服务商需要写一个服务商模块加一份模型清单：[编写服务商模块](writing-a-provider.zh-CN.md)。

### 这些服务商对着真实服务测过吗

内置的高瑞模型已经对着真实服务运行过；OpenAI 和 Google Gemini 按官方文档接入，项目还没有实际运行过。S3 存储驱动是对着 MinIO 测试的；AWS S3、Cloudflare R2、阿里云 OSS 没有对着真实服务跑过（见[存储](storage.zh-CN.md#测试情况)）。请在自己的环境里确认，并欢迎反馈结果。
