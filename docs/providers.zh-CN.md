# 模型接入

[English](providers.md)

LoomCanvas 本身没有模型。**模型接入**用你的 Key 把它连到一个上游接口。这一页说明内置的接入类型、各自提供的模型、参考素材怎么送到上游，以及价格怎么填。

> 内置的几种接入在本项目里都还没有对着真实上游跑过。它们的请求和响应格式由针对「假上游」的测试固定下来（`server/test/providers.test.js`）。第一次真实运行请当作验证，发现不一致请反馈。

## 概念

| 名词 | 含义 |
| --- | --- |
| 接入类型 | `server/src/providers/` 下的一个插件，懂一种接口格式。内置三种。 |
| 接入（实例） | 一种类型加上你的接口地址和 API Key，在「设置 → 模型接入」里添加。同一类型可以加多个，总数最多 50 个。 |
| 标识（slug） | 实例创建时得到的短标识，取自类型名：`gaorui`，再加就是 `gaorui-2`，以此类推。之后不会变。 |
| 模型标识 | `<标识>:<上游模型名>`，例如 `gaorui:nano-banana-2`。画布、价格和用量都用它指代模型。 |

需要知道的几点：

- API Key 加密后才入库，任何接口都不会返回它。界面上只显示是否已设置和末四位。修改接入时，Key 留空表示保持不变。
- 「测试连接」是向上游要一次模型列表，验证的是地址和 Key，不是每个模型。
- 每个接入的模型列表缓存五分钟。保存或测试接入会刷新它。上游连不上时，继续使用上一次拿到的列表。
- 停用接入后，它的模型都不会出现在画布上。删除接入会同时删除其模型的价格和显示覆盖项。已有的运行记录保留。
- 接口地址由部署者填写，原样使用，所以可以指向内网里的服务。发往它的请求不跟随重定向，API Key 不会被带到别的主机。

## 内置类型

### 高睿 API

推荐：一个 Key 可用下表的图片、视频模型和对话模型。在 <https://gaorui.cc> 获取 Key。

| 字段 | 必填 | 默认值 |
| --- | --- | --- |
| API Key | 是 | |
| 接口地址 | 否 | `https://gaorui.cc` |

模型来自 LoomCanvas 自带的清单（`server/src/providers/catalog/gaorui.json`）：

| 模型标识（冒号后面的部分） | 名称 | 类型 | 参考图 | 比例 | 分辨率 | 时长 |
| --- | --- | --- | --- | --- | --- | --- |
| `nano-banana-pro` | Nano Banana Pro | 图片 | 最多 8 张 | auto、1:1、2:3、3:2、3:4、4:3、4:5、5:4、16:9、9:16、21:9 | 1K、2K、4K | |
| `nano-banana-2` | Nano Banana 2 | 图片 | 最多 8 张 | 同上 | 1K、2K、4K | |
| `nano-banana-2.1` | Nano Banana 2.1 | 图片 | 最多 8 张 | 同上 | 1K、2K、4K | |
| `nano-banana-2-lite` | Nano Banana 2 Lite | 图片 | 最多 8 张 | 同上 | 1K | |
| `omni-flash` | Omni Flash | 视频 | 最多 5 张，或首帧 + 尾帧 | 16:9、9:16 | 720p、1080p、4k | 6、8、10 秒 |
| `omni-flash-edit` | Omni Flash Edit | 视频编辑 | 最多 5 张，另需一个原视频 | 16:9、9:16 | 720p、1080p、4k | |
| `sora-2-openai-12s` | Sora 2 (12s) | 视频 | 1 张 | 9:16、16:9 | | 固定 12 秒 |
| `grok-imagine-video-1.5-preview` | Grok Video 1.5 | 视频 | 最多 5 张 | 9:16、16:9、1:1、3:2、2:3 | 480p、720p | 4、6、8、10、12、15 秒 |

- 这些都是异步的：LoomCanvas 先提交任务，再轮询结果。
- 视频编辑节点里只有 `omni-flash-edit` 可选。
- **对话模型**从上游的 `/v1/models` 读取。这个列表不说明模型是做什么的，所以名字看起来像素材模型的（图片、视频、音频、向量等）会按名字规则排除。排除错了的，可以在「设置 → 模型」里手动停用。
- 清单里不带价格。见[价格](#价格)。

### OpenAI 兼容接口

适用于 OpenAI 官方，以及使用 OpenAI 接口格式的中转和自建网关。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 接口地址 | 是 | `https://host` 和 `https://host/v1` 都可以。 |
| API Key | 否 | 网关不需要认证时留空。 |
| 对话模型 | 否 | 模型名，逗号分隔。 |
| 图片模型 | 否 | 模型名，逗号分隔。 |

会出现哪些模型：

- 两个列表只要填了一个，就只出现填的这些模型。
- 两个都留空时，从 `GET /v1/models` 读取。名字像图片模型的（`dall-e`、`gpt-image`、`image`、`imagen`、`flux`、`stable-diffusion`、`sdxl`、`midjourney`、`seedream`、`kolors`）算图片模型；向量、重排、审核、语音、视频类模型跳过；其余算对话模型。

能力：

| 类型 | 接口 | 支持什么 |
| --- | --- | --- |
| 对话 | `POST /chat/completions` | 文本，外加最多 8 张图（`image_url` 形式），外加一个视频（`video_url` 形式，视频分析用）。 |
| 图片 | `POST /images/generations` | **只支持文生图。** 不会发送参考图，本接入不调用 `/images/edits`。比例可选 `auto`、`1:1`、`3:2`、`2:3`（分别发送 `1024x1024`、`1536x1024`、`1024x1536`；`auto` 不发送尺寸）。 |

不支持视频生成。请求会一直等到图片生成完，所以受的是图片超时的限制，而不是较短的提交超时。

### Google Gemini

适用于 Gemini API，或使用同样格式的代理。

| 字段 | 必填 | 默认值 |
| --- | --- | --- |
| API Key | 是 | |
| 接口地址 | 否 | `https://generativelanguage.googleapis.com` |
| 模型 | 否 | 逗号分隔。留空表示向接口查询。 |

会出现哪些模型：

- 「模型」留空时，从接口读取（支持 `generateContent` 的模型）。
- 名字里带 `image`（`imagen` 也在内）或 `banana` 的算图片模型，其余算对话模型。手动填写的名字也按这个规则判断。

能力：

| 类型 | 支持什么 |
| --- | --- |
| 图片 | 生成和编辑，最多 8 张参考图。比例：auto、1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9。 |
| 对话 | 文本，外加最多 8 张图。不能输入视频：视频分析节点里不会列出 Gemini 的对话模型，带视频的对话请求会被拒绝（`model.no_video_input`）。 |

不支持视频生成。和 OpenAI 兼容接口一样是同步的。

## 哪个节点用哪类模型

| 节点 | 可选模型 |
| --- | --- |
| 图片生成、图片编辑 | 图片模型 |
| 视频生成 | 视频模型（不含视频编辑专用的） |
| 视频编辑 | 标记为视频编辑的视频模型 |
| 大语言模型 | 对话模型 |
| 视频分析 | 能输入视频的对话模型（`acceptsVideo`） |

视频分析是把视频交给对话模型。内置类型里，高睿 API 和 OpenAI 兼容接口的对话模型声明可以输入视频，视频以 `video_url` 内容片段的形式带上；Gemini 的对话模型不行。`video_url` 是中转服务里常见的扩展，不属于 OpenAI 官方接口，能不能用取决于你的上游和模型：模型不认的话，显示的是上游返回的错误。它一定需要公网可访问的地址。

## 素材怎么送到上游

画布上的参考图和原视频是存在**你自己**存储里的文件，上游模型得能读到它们。各接入用的是下面三种方式之一：

| 方式 | 谁在用 | 没有公网地址时 |
| --- | --- | --- |
| 内联 base64 | Gemini（始终如此） | 可以用。 |
| 有公网地址就给地址，否则内联 data URI | 高睿的图片模型、Omni Flash、Omni Flash Edit 的参考图、Sora 2；OpenAI 格式对话里的图片 | 可以用。图片内联发送，每张最大 20 MB。 |
| 只能给地址 | Omni Flash Edit 的**原视频**、Grok Video 的参考图、对话里的视频 | **失败**，提示「…需要公网可访问的地址…」。 |

「公网地址」指 `http(s)` 的地址，且不是 `localhost`、不是内网 IP。文件在下面两种情况下有公网地址：

- 文件在 S3 兼容的桶里，而且桶的 Endpoint 能从公网访问。这时上游拿到的是桶的公开地址（`redirect` 分发时），或者一个有效期一小时的预签名地址。桶可以是私有的，也不需要 `PUBLIC_URL`；或者
- `PUBLIC_URL` 是你的公网地址。把文件交给上游时，会把它拼到文件的站内相对地址（`/files/<key>`）前面。本地磁盘上的文件只有这一条路。

所以要做视频编辑，或者用「只能给地址」的模型做图生视频，要么把 `PUBLIC_URL` 设成公网地址，要么把文件存到桶里（「设置 → 存储」）。切换存储不会搬动已经存下的文件。见[存储](storage.zh-CN.md#给上游模型的参考素材)和[部署](deployment.zh-CN.md#public_url)。

预签名地址会发给上游服务商，拿到它的人在过期前可以读取那一个文件。它不会存进画布或运行记录。

结果回来的方式都一样：LoomCanvas 把上游的结果下载下来（经过 [SSRF 防护](security.zh-CN.md#ssrf-防护)），存进你的存储，图片会生成缩略图。

## 价格

LoomCanvas 不知道你的上游怎么收费。你把自己实际支付的单价填进来，它据此在运行按钮旁显示预估，并汇总用量。价格不会影响上游向你收多少钱。

![模型页](images/08-settings-models.png)

*截图里的价格是为了截图临时填的。新装的实例没有任何价格。*

### 填写价格

打开「设置 → 模型」，找到模型，点「设置价格」。

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| 货币 | `CNY`、`USD` 这样的代码 | 和金额一起显示。不同货币的金额不会相加。 |
| 计费单位 | `per_image`（每张）、`per_video`（每条）、`per_second`（每秒）、`per_1m_tokens`（每百万 token） | 一个单价买到的是什么。 |
| 价格随什么变化（`by`） | 不变、`resolution`（分辨率）、`duration`（时长）、`resolution_duration`（分辨率 + 时长） | 是固定价还是查表。 |
| 价格 / 价格表 | 不小于 0 的数字，或若干行「档位 → 价格」 | 单价。 |

价格表的键，与运行参数匹配时不区分大小写：

| `by` | 键 | 例子 |
| --- | --- | --- |
| `resolution` | 分辨率 | `1K`、`720p` |
| `duration` | 时长的秒数 | `6`、`10` |
| `resolution_duration` | `"<分辨率>:<秒数>"` | `720p:6`、`1080p:10` |

金额怎么算：

| 单位 | 预估 |
| --- | --- |
| `per_image`、`per_video` | 单价 × 数量 |
| `per_second` | 单价 × 时长秒数 × 数量 |
| `per_1m_tokens` | 运行前不预估。运行结束后按上游返回的 token 用量计算。可以填一个统一单价，或者通过接口分别填 `input` 和 `output` 的单价。 |

用接口写入同样的结构（数字只是占位，不是真实价格）：

```bash
curl -X PUT 'http://localhost:3000/api/admin/models/gaorui%3Anano-banana-2' \
  -H 'Content-Type: application/json' \
  -d '{"pricing":{"currency":"CNY","unit":"per_image","by":"resolution","table":{"1K":0.1,"2K":0.2,"4K":0.4}}}'
```

发送 `"pricing": null` 可以去掉你填的价格。模型标识要做 URL 编码。完整说明见 [API](api.md#models-admin)。

### 「成本未知」是什么意思

算不出金额时，成本就是**未知**：

- 模型没有填价格；
- 价格表里没有当前分辨率或时长对应的那一行；
- 按秒计价，但模型没有时长参数；
- 模型按 token 计价，而上游没有返回用量。

未知不会被当成 0 或免费。模型照样可以运行。在用量汇总里，成本未知的运行单独计数（「另有 N 次运行成本未知」）。

工具节点（切片、拼图、加水印、改尺寸、多平台导出）在你自己的服务器上处理，不调用模型，没有成本。

### 记录下来的成本是什么

- 图片和视频运行：记录的是提交时算出的预估。
- 按 token 计价的对话运行：运行结束后按返回的用量计算。
- 这是按你的价格表估算的。真实账单以上游为准。

## 用量记录

每一次运行都会记录：模型、状态、提示词（列表里显示前 200 个字符）、参数、成本、失败原因和时间。

「设置 → 用量」里可以看到：

- 某个日期范围内按天或按模型的汇总：运行次数、成功、失败、取消、各货币的预估花费，以及成本未知的次数；
- 逐条记录，最新的在前。

只有**成功**且成本**已知**的运行计入花费。即使 `retentionDays` 清掉了结果文件，记录仍然保留。

同样的数据可以通过 `GET /api/admin/usage` 和 `GET /api/admin/usage/records` 取得，见 [API](api.md#usage)。
