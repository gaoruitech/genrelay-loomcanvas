# 服务商

[English](providers.md)

LoomCanvas 本身没有模型。你选一家**服务商**，填入自己的 API Key，这家服务商支持的模型就可以在画布上使用。这一页说明内置的三家服务商、每家支持的模型、自定义模型、怎么改接口地址、从上一个版本升级、参考素材怎么送到上游，以及价格怎么填。

> 状态：内置的高瑞模型已经对着真实服务运行过；OpenAI 和 Google Gemini 按官方文档接入，项目还没有实际运行过。这两家第一次真实运行请当作一次测试，发现不一致请反馈。

## 概念

服务商就是服务商，模型就是模型。一家服务商有哪些模型，写在 LoomCanvas 自带的清单里。不会根据模型的名字去推断任何东西，也不会向上游读取模型列表。

| 名词 | 含义 |
| --- | --- |
| 服务商 | 提供接口的那家公司：高瑞、OpenAI 或 Google Gemini。在代码里是 `server/src/providers/` 下的一个模块加一份模型清单。 |
| 模型清单 | 一家服务商支持的模型，手工写在 `server/src/providers/catalog/<服务商标识>.json` 里，分图片（image）、视频（video）、对话（chat）三段。模型写在哪一段，就是哪种类型。 |
| 添加的服务商（实例） | 一家服务商加上你的 API Key，在「模型管理」页添加。服务商属于添加它的那个账号：每个账号有自己的服务商、Key、模型和价格。同一家可以添加多次（例如两个 Key），每个账号最多 50 个。添加后不能更换服务商。 |
| 自定义模型 | 清单里没有、由你手动加到某个已添加的服务商下面的模型，类型由你指定。见[自定义模型](#自定义模型)。 |
| 标识（slug） | 添加服务商时得到的短标识，取自服务商标识：`gaorui`，再加就是 `gaorui-2`，以此类推。之后不会变。 |
| 模型标识 | `<标识>:<上游模型名>`，例如 `gaorui:nano-banana-2`。画布、价格和用量都用它指代模型。 |

需要知道的几点：

- 一个服务商下面的模型 = 这家服务商的模型清单 + 你给它添加的自定义模型。这个列表在本地拼出来，保存或测试服务商都不会改变它。
- API Key 必填。它加密后才入库，任何接口都不会返回它。界面上只显示是否已设置和末四位。编辑服务商时，Key 留空表示保持不变。
- 「测试连接」会调用上游的模型列表接口，只用来证明地址和 Key 可用，返回的列表本身不使用。
- 停用服务商后，它的模型都不会出现在画布上。删除服务商会同时删除它的自定义模型，以及其模型的价格和显示覆盖项。已有的运行记录保留。
- 侧栏的「模型管理」页左边是你的服务商卡片，每张卡片上有状态、Key 是否已设置、模型数量，以及「测试连接」和「编辑」。点一张卡片，右边就是这个服务商的模型，按图片、视频、对话分组。表格上方的一条筛选可以按类型、状态（已启用 / 已停用）、来源（内置 / 自定义）、价格（已设置价格 / 未设置价格）筛选，也可以按显示名称或模型 ID 搜索。自定义模型带「自定义」标记。每一行开头的开关用来启用或停用模型；行里的「更多操作」可以改显示名称和排序。筛选条件记在浏览器里。

## 服务商

新账号注册后看到的「添加一个服务商」页，以及「模型管理」页的「添加服务商」里，都按下面的顺序列出。选中一家后，表单里有 API Key、可选的名称、「此服务商支持的模型」列表，以及「高级」。

| 服务商 | 标识 | 默认接口地址 | 使用的接口 |
| --- | --- | --- | --- |
| 高瑞（推荐） | `gaorui` | `https://gaorui.cc` | 高瑞自己的接口 |
| OpenAI | `openai` | `https://api.openai.com/v1` | 只走 OpenAI 官方接口 |
| Google Gemini | `gemini` | `https://generativelanguage.googleapis.com` | 只走 Gemini 官方接口 |

| `gemini-3.5-flash-c` | Gemini 3.5 Flash | 对话 | 可读图片，最多 8 张；可读视频 | | | |

- **对话模型。** 清单里有五个。`deepseek-v4-pro`、`gpt-5.5`、`glm-5.3` 是纯文本模型；`gpt-6-astra` 可以读图片；`gemini-3.5-flash-c` 可以读图片和视频。它们走 `POST /v1/chat/completions`（OpenAI 格式）。五个里只有 `gemini-3.5-flash-c` 能输入视频，所以清单里的模型只有它出现在视频分析节点里；视频怎么发见[哪个节点用哪类模型](#哪个节点用哪类模型)。清单里没有的高瑞对话模型，仍然可以作为[自定义模型](#自定义模型)添加，类型选「对话」。
- **纯文本对话模型。** 纯文本模型不会收到图片。在大语言模型节点里，它的图片输入口会变灰，不能再接新的连线；如果已经连着图片，节点上会写明这些图片不会发送，运行时只带文字。对这类模型调用 `POST /api/llm/tasks` 并带上 `imageUrls` 会被拒绝（`model.no_image_input`）。
- 图片和视频模型是异步的：LoomCanvas 先提交任务，再轮询结果。
- 视频编辑节点里只有 `omni-flash-edit` 可选。
- 每个视频模型有自己的请求体，逐个写在 `server/src/providers/gaorui.js` 里。
- **Omni Flash 和 Veo 3.1 在上游各对应几个模型名。** `omni-flash` 按时长发 `omni_flash_8s` 或 `omni_flash_10s`（上游还列着 `omni_flash_6s`，但没有渠道提供，所以不提供 6 秒）。`veo-3.1` 按输入发三个模型名之一：没有图片是 `veo_3_1`，多图参考是 `veo_3_1-components`（最多 3 张），首尾帧是 `veo_3_1-fl`（首帧、尾帧各一张）。Veo 的分辨率 `lite` 是上游的「快速版」档位，出片是 1280×720。Veo 的图片只能给公网地址。
- **Omni Flash 没有 6 秒，也没有 4k。** Omni Flash 提供 720p 和 1080p，和高瑞主站一致（上游也收 4k，这里不提供）。Omni Flash Edit 没有分辨率可选：视频编辑一律按 720p 发送，主站也是这样做的。节点里还存着已经不提供的值时会回落：6 秒变成 8 秒，4k 变成 720p。
- **Grok Video。** Grok Video 1.5 最短是 6 秒（请求 4 秒，返回的是 6 秒的视频），所以不提供 4 秒；存着 4 秒的节点会按 6 秒发送。Grok Video 1.0（`grok-imagine-1.0-video`）的时长是 6、10、15 秒三档，画质只有 480p 一档，发送时写成 `quality: "standard"` 加 `resolution: "480p"`；参考图多于一张时最长 10 秒。两个模型都只提供 9:16、16:9、1:1 三种比例：1.5 请求其他比例会被服务拒绝，1.0 请求 3:2 时服务照收，但返回的是 16:9 的视频。两个模型的参考图都只能给公网地址（`image_urls`）。
- **图片模型的参考图必须有公网地址。** 该服务不接受内联（base64）的图片，会返回 HTTP 400 `image_must_be_url`。所以实例没有公网地址时，用高瑞的图片模型做图生图会在发出请求之前失败，提示「…需要公网可访问的地址…」，见[素材怎么送到上游](#素材怎么送到上游)。文生图不受影响。
- **只凭 Key，没有办法把本地文件传给高瑞。** 它的公开接口里没有这样的入口：`/v1/uploads`、`/v1/upload` 不存在（404）；`/v1/assets/uploads` 存在，但它是给已经有公网地址的素材做登记的（参数是 `url`，供 Seedance 模型使用），返回的是 `asset://` 标识，不是图片模型能收的地址；`/v1/files` 是一个中转路由，要求带模型名。所以 LoomCanvas 没法替你绕过「没有公网地址」这件事，而是在运行之前就说清楚：节点用的是这类模型、连着图片、实例又既没有公网的 `PUBLIC_URL`、也没有公网能访问的存储桶时，节点上会写明原因和做法，点运行也会停在这里，不会发出任何请求。

调用的接口：

| 类型 | 接口 | 说明 |
| --- | --- | --- |
| 对话 | `POST /chat/completions` | 文本，外加图片（`image_url` 形式）。视频会被拒绝（`model.no_video_input`）：官方接口没有视频这种内容片段。 |
| 图片，没有参考图 | `POST /images/generations`（JSON） | `{ model, prompt, n, size? }` |
| 图片，接了参考图 | `POST /images/edits`（multipart） | `model`、`prompt`、`n`、`size?`，每张参考图一个 `image[]` 文件部分。 |

- 比例 `1:1`、`3:2`、`2:3` 分别以 `size` `1024x1024`、`1536x1024`、`1024x1536` 发送；`auto` 不发送尺寸。
- 结果以 `b64_json` 或 `url` 返回都能处理。
- 请求会一直等到图片生成完，所以受的是图片超时的限制，而不是较短的提交超时。

## 自定义模型

自定义模型是服务商的模型清单里没有的模型。它属于某一个已添加的服务商。

添加方法：打开「模型管理」页，选中那个服务商，点模型表格上方的「添加自定义模型」。

| 字段 | 规则 |
| --- | --- |
| 模型名 | 必填。上游接口里的模型名，原样发送。只能用字母、数字和 `. _ - : / @`，最长 120 个字符。之后不能修改：需要换名字请删除后重新添加。 |
| 类型 | 必填。图片或对话，由你手动选择。没有默认值，LoomCanvas 不会根据名字去猜。 |
| 显示名称 | 可选。默认用模型名。 |

规则：

- 自定义模型不能和服务商清单里的模型重名。如果后来的版本把某个模型加进了清单，而你已经用同样的名字加过自定义模型，就以清单里的为准：模型标识不变，所以它的启用状态、排序、显示名称和价格都保留，画布照常可用；它的能力改为清单里写的那样（纯文本的不再接受图片；高瑞的对话模型里只有 `gemini-3.5-flash-c` 仍然接受视频）；那条自定义记录在服务端启动时删除。
- 每个服务商最多 100 个自定义模型。
- **三家服务商都不能添加自定义视频模型。** 高瑞：每个视频模型的请求体都不一样，没有一个通用的可以发。OpenAI 和 Gemini：这里没有通过它们的官方接口实现视频。
- 类型和显示名称可以修改。删除自定义模型会同时删除它的价格和显示覆盖项；画布里选了它的节点需要重新选模型。

自定义模型没有自己的一套参数，用的是按服务商和类型固定的一套：

| 服务商 | 类型 | 怎么发送 | 图片 | 比例 | 其他 |
| --- | --- | --- | --- | --- | --- |
| 高瑞 | 图片 | nano-banana 任务接口（`POST /v1/nano-banana`，之后轮询） | 参考图最多 8 张 | auto、1:1、2:3、3:2、3:4、4:3、4:5、5:4、16:9、9:16、21:9 | 分辨率 1K、2K、4K |
| 高瑞 | 对话 | `POST /v1/chat/completions`，OpenAI 格式 | 可读图片，最多 8 张 | | 视频以 `image_url` 内容片段带上（和清单里的 `gemini-3.5-flash-c` 是同一种发法），所以视频分析节点里会列出它；模型实际读不读得了视频由上游决定。清单里的高瑞对话模型不一样：各自能读什么见上面的表。 |
| OpenAI | 图片 | `POST /images/generations`；接了参考图时是 `POST /images/edits` | 参考图最多 16 张 | auto、1:1、3:2、2:3 | 数量 1 到 4。没有分辨率选项。 |
| OpenAI | 对话 | `POST /chat/completions` | 可读图片，最多 8 张 | | 不能输入视频。 |
| Gemini | 图片 | `generateContent` | 参考图最多 8 张 | auto、1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9 | 没有分辨率选项：用模型自己的默认尺寸。 |
| Gemini | 对话 | `generateContent` | 可读图片，最多 8 张 | | 不能输入视频。 |

这几套参数就是 `server/src/providers/gaorui.js`、`openai.js`、`gemini.js` 里的 `CUSTOM` 常量。你添加的模型如果不接受其中某个参数，显示的是上游返回的错误。

## 高级：修改接口地址

每家服务商默认用它的官方地址。只要你没改过，添加的服务商不会单独保存地址。

要修改，在添加或编辑对话框里展开「高级」，改「接口地址」。「恢复官方地址」可以改回默认值。地址不是官方地址的服务商，在列表里带「非官方地址」标记。

- 改成别的地址（代理或中转）时，对方必须使用与官方完全相同的接口。LoomCanvas 不为第三方的私有格式做适配。
- 高瑞一般不需要修改。
- 可以接受的写法：OpenAI，`https://host` 和 `https://host/v1` 都可以；高瑞，末尾的 `/v1` 会被忽略；Gemini，末尾的 `/v1` 或 `/v1beta` 会被忽略。
- 接口地址由部署者填写，原样使用，所以可以指向内网里的服务。发往它的请求不跟随重定向，API Key 不会被带到别的主机。

## 从上一个版本升级

上一个版本里有「类型」（其中一种叫 `openai-compatible`）、自由填写的模型字段、从上游读取的模型列表，以及按名字猜出来的模型类型。它保存下来的服务商会在服务端启动时自动转换，每个只转换一次，不需要你做任何操作。服务端日志里会记下升级了几个服务商、带过来几个自定义模型。

升级做了什么：

- 类型为 `openai-compatible` 的变成 `openai` 服务商。它的标识（slug）不变，所以画布、价格和用量里像 `openai-compatible:gpt-4o-mini` 这样的模型标识照常可用。
- 填在旧字段里的模型变成自定义模型。OpenAI 的两个字段本身就说明了类型（对话模型、图片模型）。Gemini 只有一个字段，所以旧规则在升级过程里最后用一次，也只在这里用：名字里带 `image` 或 `banana` 的算图片模型，其余算对话模型。
- 旧版本向上游读取列表的那些情况（高瑞的对话模型；OpenAI 和 Gemini 字段留空时）没有保存下来的列表可以转换。实际用过的模型从已有的记录里找回：每次历史运行记录的类型，以及画布上选了这个模型的节点的类型。只出现在列表里、从没运行过也没在画布上选过的模型不会带过来；需要的话请作为自定义模型添加。
- 名字已经在服务商清单里的模型不需要自定义条目，会跳过。
- 自定义模型只能是图片或对话，所以只存在于旧字段或上游列表里的视频模型不会带过来。
- 高瑞服务商的名称如果还是旧的默认名「高瑞 API」（在英文界面下添加的是 "Gaorui API"），改成现在的默认名「高瑞」（"Gaorui"）。名称只要不是恰好等于旧默认名就不动，别家服务商的名称也不动。已经按上面几条升级过、但还叫旧默认名的服务商，下次启动时也会补改这一次；之后不再检查，所以你以后特意起名「高瑞 API」会保留。
- API Key、接口地址、是否启用、排序和模型覆盖项（启用状态、名称、价格）都不动。

升级之后：

- 每个服务商下面还会列出它那一家清单里的全部模型。不需要的可以在「模型管理」页停用。
- 你填过的接口地址会保留。原来是 `openai-compatible`、指向中转的服务商，那个中转必须使用 OpenAI 官方接口：对话请求里的视频现在会被拒绝，参考图现在发往 `/images/edits`。
- 请到「模型管理」页核对带过来的 Gemini 模型的类型，按名字判断可能出错。自定义模型的类型可以修改。

## 哪个节点用哪类模型

| 节点 | 可选模型 |
| --- | --- |
| 图片生成、图片编辑 | 图片模型 |
| 视频生成 | 视频模型（不含视频编辑专用的） |
| 视频编辑 | 标记为视频编辑的视频模型 |
| 大语言模型 | 对话模型 |
| 视频分析 | 能输入视频的对话模型（`acceptsVideo`） |

视频分析是把视频交给对话模型，所以只列出能输入视频的对话模型：

- 高瑞清单里的 `gemini-3.5-flash-c`；
- 高瑞服务商下的**自定义对话模型**。它实际读不读得了视频由上游决定。

OpenAI 和 Gemini 的对话模型（清单里的和自定义的）会拒绝视频，高瑞清单里另外四个对话模型不能输入视频，所以都不会列出。

发给高瑞的请求里，视频放在一个 **`image_url` 内容片段**里，值是视频的公网地址。它紧跟在文字片段后面，参考图排在它后面：

```json
{ "role": "user", "content": [
  { "type": "text", "text": "<提示词>" },
  { "type": "image_url", "image_url": { "url": "https://…/clip.mp4" } },
  { "type": "image_url", "image_url": { "url": "<参考图，可选>" } }
] }
```

- 不用 `video_url`。高瑞的中转会把 `video_url` 片段丢掉而不报错，模型没有看到视频却照样给出回答。同一个视频、同一个问题，改用 `video_url` 片段发送，模型会回答没有看到视频，上游报告的输入 token 数也只有文字那一部分。
- 视频必须有公网地址，见[素材怎么送到上游](#素材怎么送到上游)。没有的话这次运行失败并说明原因，请求不会发出去。
- 这也是高瑞主站的做法。几秒钟的短视频以公网地址给出，`gemini-3.5-flash-c` 能正确描述；该服务最长能收多长的视频、视频能不能和参考图一起发，目前不清楚。

大语言模型节点只把连着的图片发给能读图片的对话模型，见[高瑞](#高瑞)一节的「纯文本对话模型」。

## 素材怎么送到上游

画布上的参考图和原视频是存在**你自己**存储里的文件，上游模型得能读到它们。各家服务商用的是下面三种方式之一：

| 方式 | 谁在用 | 没有公网地址时 |
| --- | --- | --- |
| 随请求一起发送 | Gemini（始终如此，内联 base64）；OpenAI 的参考图（作为文件部分上传到 `/images/edits`） | 可以用。每张最大 20 MB。 |
| 有公网地址就给地址，否则内联 data URI | 发给 OpenAI 和高瑞的对话请求里的图片；Omni Flash、Omni Flash Edit 的参考图 | 对话：可以用，图片内联发送，每张最大 20 MB。那两个视频模型：会内联发送；该服务那边接不接受内联图片目前不清楚，能给公网地址就给公网地址。 |
| 只能给地址 | **高瑞图片模型的参考图**（含自定义的）、Omni Flash Edit 的**原视频**、Veo 3.1 和 Grok Video（1.5 和 1.0）的参考图、对话里的视频（高瑞的 `gemini-3.5-flash-c` 和自定义对话模型） | **失败**，提示「…需要公网可访问的地址…」。参考图和视频编辑的原视频这两种情况，节点在运行之前就会说明。 |

「公网地址」指 `http(s)` 的地址，且不是 `localhost`、不是内网 IP。文件在下面两种情况下有公网地址：

- 文件在 S3 兼容的桶里，而且桶的 Endpoint 能从公网访问。这时上游拿到的是桶的公开地址（`redirect` 分发时），或者一个有效期一小时的预签名地址。桶可以是私有的，也不需要 `PUBLIC_URL`；或者
- `PUBLIC_URL` 是你的公网地址。把文件交给上游时，会把它拼到文件的站内相对地址（`/files/<key>`）前面。本地磁盘上的文件只有这一条路。

所以要用高瑞的图片模型做图生图、做视频编辑、做视频分析，或者用「只能给地址」的模型做图生视频，要么把 `PUBLIC_URL` 设成公网地址，要么把文件存到桶里（「设置 → 存储」）。切换存储不会搬动已经存下的文件。见[存储](storage.zh-CN.md#给上游模型的参考素材)和[部署](deployment.zh-CN.md#public_url)。

预签名地址会发给上游，拿到它的人在过期前可以读取那一个文件。它不会存进画布或运行记录。

结果回来的方式都一样：LoomCanvas 把上游的结果下载下来（经过 [SSRF 防护](security.zh-CN.md#ssrf-防护)），存进你的存储，图片会生成缩略图。

## 价格

LoomCanvas 不知道你的上游怎么收费。你把自己实际支付的单价填进来，它据此在运行按钮旁显示预估，并汇总用量。价格不会影响上游向你收多少钱。

![「模型管理」页](images/08-settings-models.png)

*「模型管理」页。项目不带任何价格：每个模型一开始都是「未设置」（成本未知），填上你实际支付的单价之后才有。图里的价格只是示例。*

### 填写价格

打开「模型管理」页，选中服务商，找到模型，点这一行的「设置价格」（已经有价格时是「修改价格」）。

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| 货币 | `CNY`、`USD` 这样的代码 | 和金额一起显示。不同货币的金额不会相加。 |
| 计费单位 | `per_image`（每张）、`per_video`（每条）、`per_second`（每秒）、`per_1m_tokens`（每百万 token） | 一个单价买到的是什么。 |
| 价格随什么变化（`by`） | 不变、`resolution`（分辨率）、`duration`（时长）、`resolution_duration`（分辨率 + 时长） | 是固定价还是查表。 |
| 价格 / 价格表 | 不小于 0 的数字，或若干行「档位 → 价格」 | 单价。 |

计费单位选「每百万 token」时，「价格随什么变化」换成「输入和输出」：

- 「分开计价」：填输入价格和输出价格两个数，都是每百万 token 的单价。新填对话模型的价格时默认是这一种。
- 「同一个价格」：输入和输出用同一个单价。

模型列表里，分开计价的显示成「输入 ¥1.50 / 输出 ¥6.00 · 每百万 token」这样。

价格表的键，与运行参数匹配时不区分大小写：

| `by` | 键 | 例子 |
| --- | --- | --- |
| `resolution` | 分辨率 | `1K`、`720p` |
| `duration` | 时长的秒数 | `6`、`10` |
| `resolution_duration` | `"<分辨率>:<秒数>"` | `720p:6`、`1080p:10` |

金额怎么算：

| 单位 | 预估 |
| --- | --- |
| `per_image`、`per_video` | 单价 × 数量 |
| `per_second` | 单价 × 时长秒数 × 数量 |
| `per_1m_tokens` | 运行前不预估。运行结束后按上游返回的 token 用量计算：分开计价时是 输入 token × 输入价格 + 输出 token × 输出价格，同一个价格时是（输入 + 输出）× 价格，都再除以一百万。分开计价在接口里是 `table: { "input": …, "output": … }`，同一个价格是 `price`。 |

用接口写入同样的结构（数字只是占位，不是真实价格）：

```bash
curl -X PUT 'http://localhost:3000/api/admin/models/gaorui%3Anano-banana-2' \
  -H 'Content-Type: application/json' \
  -d '{"pricing":{"currency":"CNY","unit":"per_image","by":"resolution","table":{"1K":0.1,"2K":0.2,"4K":0.4}}}'
```

发送 `"pricing": null` 可以去掉你填的价格。模型标识要做 URL 编码。完整说明见 [API](api.md#models-admin)。

### 「成本未知」是什么意思

算不出金额时，成本就是**未知**：

- 模型没有填价格；
- 价格表里没有当前分辨率或时长对应的那一行；
- 按秒计价，但模型没有时长参数；
- 模型按 token 计价，而上游没有返回用量。

未知不会被当成 0 或免费。模型照样可以运行。在用量汇总里，成本未知的运行单独计数（「另有 N 次成功运行成本未知」）。

工具节点（切片、拼图、加水印、改尺寸、多平台导出）在你自己的服务器上处理，不调用模型，没有成本。

### 记录下来的成本是什么

- 图片和视频运行：记录的是提交时算出的预估。
- 按 token 计价的对话运行：运行结束后按返回的用量计算。
- 这是按你的价格表估算的。真实账单以上游为准。

## 用量记录

每一次运行都会记录：模型、状态、提示词（列表里显示前 200 个字符）、参数、成本、失败原因和时间。

「生成记录」页里可以看到你自己这个账号的：

- 所选时间段的汇总：运行次数（分类型）、成功、失败、取消、预估花费，以及成功但成本未知的次数；
- 逐条记录，最新的在前，可以按类型、状态、模型筛选，可以看详情、导出 CSV。

「工作台」上显示本月的运行次数、成功率和预估花费，以及近 14 天每天一根柱子。见[使用指南](user-guide.zh-CN.md#生成记录)。

只有**成功**且成本**已知**的运行计入花费。即使 `retentionDays` 清掉了结果文件，记录仍然保留。

同样的数据可以通过 `GET /api/admin/usage`（按天或按模型汇总）和 `GET /api/admin/usage/records` 取得，见 [API](api.md#usage)。`from`、`to` 里只写日期时，指的是 `tz` 所给时区里的那个自然日（不带 `tz` 就是 UTC）。网页端总是带上浏览器的时区，所以「今天」就是你本地的今天。
