# 安全

[English](security.md)

怎样安全地运行一个 LoomCanvas 实例，它保护什么、不保护什么。报告漏洞请看 [SECURITY.md](../SECURITY.md)。

## 一段话说清模型

LoomCanvas 有**账号**，使用前必须登录。超级管理员账号是内置的：服务端第一次启动时自动创建，没有人靠注册成为超级管理员。能访问到实例的人都可以自己注册一个普通账号，直到超级管理员关闭注册。每个账号在自己的个人空间里只看得到自己的画布、文件、服务商、API Key 和用量。几个账号可以共用一个**团队**空间：按角色分工，成员用得上团队的 Key 但看不到它，同一张画布同一时间一个人编辑（见[团队](#团队)）。超级管理员另外负责管理站点（是否开放注册、存储、运行限制、站点名称 / Logo / 默认语言、用户列表、团队列表），但不能通过接口读取别的账号的数据，也进不了自己不是成员的团队。账号之间、团队之间靠接口隔离，不是加固过的边界：所有账号和团队共用一个进程、一个数据库、一块存储和一条队列。生成和上传的文件，对拿到地址的人是公开的。部署方案请围绕这几点来设计。

## 检查清单

1. 设一个足够长的随机 `SECRET_KEY`，并备份。
2. 第一次启动之前自己设好 `ADMIN_PASSWORD`；或者从启动日志里取出生成的超级管理员密码，第一次登录时把它换掉。换掉之前，请把第一次启动的那份日志当作敏感信息。除非能访问到实例的人都可以有账号，否则关闭注册：从第一次启动起就设 `REGISTRATION_OPEN=false`，或者用「设置 → 站点」里的开关。密码用长一些的。
3. 放在 HTTPS 后面，并在终结 TLS 的代理上发送 `Strict-Transport-Security`（应用自己不发）。
4. 在反向代理后面运行时，设置 `TRUST_PROXY`。
5. 不要直接暴露 MongoDB 和应用的端口，只对外开放代理。
6. `SSRF_ALLOW_HOSTS` 和 `CORS_ORIGIN` 没有需要就留空。
7. 把每一条分享链接、每一个文件地址都当成公开的。
8. 保持更新。

## SECRET_KEY

`SECRET_KEY` 是根密钥。加密用的密钥由它派生（HKDF-SHA256）。它只有一个用途：

| 用途 | 做什么 |
| --- | --- |
| 服务商凭据和存储密钥 | 加密数据库里每个账号的服务商 API Key，以及「设置 → 存储」里保存的 S3 Secret Access Key（AES-256-GCM，每个值一个新的随机 IV）。 |

它和登录无关。会话是存在数据库里的随机凭证（见[账号](#账号)），所以改 `SECRET_KEY` 不会让任何人退出登录。

规则：

- 至少 16 位，建议用 32 个随机字节以上。没有它服务端拒绝启动，也不会替你生成。
- 保持不变。一旦改动，已保存的服务商 Key 无法解密，每个账号都得重新填写自己的 Key。这时每个服务商都会被标记出来（`keyUnreadable`），运行会被拒绝并说明原因。保存的 S3 密钥同样解不开：服务端照常启动并记一条日志，存储设置会要求超级管理员重新填写密钥；填之前，那个桶里的文件加载不出来，如果它正是当前使用的桶，新文件会被拒绝，不会改写到别的地方。见[存储](storage.zh-CN.md#备份)。
- 它存在 `.env` 里。保护好这个文件，不要提交到版本库，并和数据库一起备份。只有数据库备份、没有密钥，Key 恢复不出来。数据库备份**加上**密钥，Key 就全暴露了。

## 账号

除[下面](#哪些是公开的)列出的公开接口外，所有接口都要求已登录的账号。没有「不用登录」的模式。

### 角色

站点上只有两种角色，没有中间档。（团队里另有三个角色，管的是团队而不是站点，见[团队](#团队)。）

| 角色 | 是谁 | 能做什么 |
| --- | --- | --- |
| `owner`（超级管理员） | 服务端第一次启动时创建（`ADMIN_*` 变量）。有且只有一个。 | 普通用户能做的它都能做，对象是它自己的数据。另外负责管理站点，也就是「设置」里只有超级管理员看得到的那几个分区：存储、运行限制（并发、超时、重试、保留期）、站点名称 / Logo / 默认语言、是否开放注册、用户列表（停用或启用账号、删除账号、重置密码、授权创建团队），以及团队列表（见[团队](#团队)）。 |
| `user`（用户） | 其余所有账号：注册产生的都是它。 | 在自己的个人空间里工作：画布、自己发布的分享链接、资产、品牌包、运行、用量记录、保存的模板，以及自己的服务商、API Key、自定义模型和价格；也在它加入的团队里工作。 |

超级管理员这个角色管的是站点，不是别人的数据。超级管理员的请求和其他人一样，只落在自己的数据上。用户列表里每个账号只有用户名、邮箱、状态、加入和担任团长的团队数，以及两个数字（个人空间里的画布数和运行数），没有内容。超级管理员不能在用户列表里停用、删除或重置超级管理员账号。

超级管理员在启动时创建：还没有 `owner` 角色的账号时，服务端按 `ADMIN_USERNAME`（默认 `admin`）、`ADMIN_PASSWORD`、`ADMIN_EMAIL` 建一个。这几个变量只在那一刻读取：之后都被忽略，已有的超级管理员不会被环境变量覆盖。注册产生不了超级管理员，所以不存在抢这个角色的问题，几个进程同时启动时也一样。见[部署](deployment.zh-CN.md#账号)。

### 隔离了什么，没隔离什么

- 接口的每一次查询都限定在一个空间内：发起请求的账号的个人空间，或者一个现查过成员身份的团队（见[团队](#团队)）。列表不会混入别的空间的数据。按 id 访问别的账号的画布、运行、服务商或资产，得到的是 404，和 id 不存在时一样。
- 服务商的 Key 按空间分开：个人空间里是账号自己的，团队里是团队的。一次运行用的是它所属空间的服务商和 Key，重启后续跑时也一样。
- 内置模板、内置提示词片段和只读的素材库属于站点，所有人都能看到。
- **分享链接和文件地址本来就是跨账号的。** 拿到分享链接的人不用登录就能读到快照，已登录的账号可以把它复制进自己的画布。`/files/<key>` 对拿到地址的人公开。新文件的 key 里带着所属空间的 id：账号 id（`uploads/<账号 id>/…`），团队的文件则是团队 id，为的是删除账号或团队时能把它的文件一起删掉；这一段不是访问控制。
- **这不是加固过的多租户边界。** 所有账号共用一个进程、一个数据库、一块存储和一条队列。能读数据库或服务器磁盘的人什么都能读到；服务商的 Key 仍然是用 `SECRET_KEY` 加密的。

### 会话

- 登录后得到一个凭证：32 个随机字节，本身不含任何信息。浏览器在每个请求里用 `Authorization: Bearer <token>` 带上它。服务端只在 `sessions` 集合里保存它的 SHA-256，以及所属账号、过期时间、最近一次使用的时间、浏览器的 User-Agent 和客户端地址。
- 会话有效期 12 小时；登录时选了「记住我」是 30 天。时间从登录那一刻算起，使用过程中不会顺延。
- 会话存在数据库里，所以结束会话是立即生效的：退出登录、结束另一台设备上的会话、修改密码、重置密码、停用账号、删除账号。
- 修改密码会结束这个账号的**全部**会话，包括发起修改的这一个。响应里带着给调用方的一个新凭证，有效期是被替换掉的那个会话剩下的时间，网页端会悄悄换上，用的人感觉不到。修改之前被人从浏览器里拷走的凭证就此作废。重置密码（超级管理员重置，或命令行重置）结束全部会话，不发新凭证。
- 每个账号都可以在「设置 → 账号与安全」里列出自己当前的会话，并结束其中任何一个。
- 网页端把凭证存在浏览器的本地存储里，键是 `loomcanvas-token`：登录时勾了「记住我」放在 `localStorage`，没勾放在 `sessionStorage`（关掉标签页就没了）。能用这个浏览器配置的人就等于登录了，直到会话过期，或者从别的设备上把它结束。
- 整个过程不用 cookie，所以不存在跨站请求伪造的问题。放在本地存储里的凭证怕的是页面里跑起来的脚本（XSS）；防它的是内容安全策略：不允许内联脚本，也不允许别的来源的脚本（见[浏览器端的保护](#浏览器端的保护)）。

### 密码

- 8 到 128 个字符，没有别的组成要求。
- 以 scrypt 哈希保存（`N=32768, r=8, p=1`），每个账号一个 16 字节的随机盐，参数和哈希存在一起。比较用恒定时间。凭证不会写进日志，密码也不会，只有下面说的这一个例外。
- **生成的超级管理员密码会在启动日志里打印一次。** 创建超级管理员时如果没设 `ADMIN_PASSWORD`，服务端生成一个 16 位的随机密码，在那一次启动的日志里用一个框打印出来。数据库里只存它的哈希，以后不会再打印。这个账号第一次登录时必须把它换掉，换过之后日志里的那个值就没有用了。在这之前，能读到这份日志的人就能以超级管理员身份登录，所以请把它当作敏感信息；自己设了 `ADMIN_PASSWORD` 的话，日志里什么都不会打印。
- **别人知道的密码一定会被换掉。** 生成的超级管理员密码、超级管理员「重置密码」给出的临时密码、命令行重置给出的临时密码，都会给账号打上标记（`mustChangePassword`）。标记还在的时候，这个账号的会话只能做四件事：查看自己是谁（`GET /api/auth/me`、`GET /api/bootstrap`）、修改密码（`PUT /api/auth/password`）、退出登录。其余需要登录的接口一律返回 403 `auth.password_change_required`，网页端也只显示「设置新密码」这一屏。新密码不能和临时密码相同。
- 账号不存在和密码错误，登录接口给出同样的回答，花的工夫也一样。账号被停用这件事，只有输对密码之后才会被告知。
- 系统不发任何邮件，所以没有「找回密码」邮件。忘了密码，由超级管理员在「设置 → 用户管理」里重置，或者由运行服务端的人用命令行重置（`node server/src/cli/reset-password.js <用户名或邮箱>`）。超级管理员自己的密码只能用命令行重置。两种方式都会给出一个只显示一次的临时密码，结束该账号的所有会话，并要求下次登录时先设置新密码。见[部署](deployment.zh-CN.md#忘记密码)。

### 限流

登录尝试按四种口径计数，时间窗都是 10 分钟：

| | 数的是什么 | 每 10 分钟上限 |
| --- | --- | --- |
| (a) | 同一个客户端地址对同一个账号名 | 10 次 |
| (b) | 同一个客户端地址，不论试的是哪个账号名 | 30 次 |
| (c) | 同一个账号名，不论尝试来自哪些地址 | 100 次 |
| (d) | 全部登录尝试合计 | 3000 次 |

另外还有两条：

| 对象 | 上限 |
| --- | --- |
| 同一个客户端地址的注册尝试 | 每小时 20 次 |
| 修改用户名或邮箱（`PUT /api/auth/profile`） | 每个账号每小时 20 次 |

- IPv6 客户端按它所在的 /64 网段计。
- 登录成功会清掉这个账号名和这个地址在 (a) 上的计数。
- **猜某个账号名，不会把它的主人锁在外面。** (c) 和 (d) 对这个账号的「熟悉地址」不生效：最近 30 天里这个账号从那里成功登录过的地址，或者持有这个账号有效会话的地址。所以从很多地址轮流猜同一个账号名，会被压到每 10 分钟 100 次，而账号的主人从平时用的地址照样能登录。主人要是换了一个这个账号从没用过的地址，在这种猜测进行期间可能要等一等。
- 账号名不必存在。对一个没人用的名字，这些限制的表现完全一样，所以看不出哪些名字存在。
- 修改密码时输错当前密码，计入 (a) 和 (c)，所以偷到一个会话也没法无限制地猜密码。
- 超限时返回 HTTP 429，错误码 `auth.too_many_attempts`，响应体里有 `data.retryAfterSeconds`，响应头里有 `Retry-After`。已经登录的会话始终不受影响。
- 这些计数，以及「账号从哪些地址登录过」的记录，都在内存里，每个进程各一份。重启后清空（有效会话所在的地址仍然算熟悉地址），并且假设只有一个进程。

### 注册

注册只会产生普通用户（`role: "user"`），没有办法通过注册成为超级管理员。注册默认开放。陌生人能访问到的实例，请把它关掉：第一次启动之前设 `REGISTRATION_OPEN=false`，或者超级管理员在「设置 → 站点」里把「开放注册」关掉，或者调用 `PUT /api/admin/site`，请求体 `{ "registrationOpen": false }`。已有的账号照常登录，新的注册不了，没有例外。`REGISTRATION_OPEN` 只给这项设置一个初始值；设置保存过之后，以存下的值为准。

开放注册意味着：每个账号都能使用实例的存储和队列（受 `userQueueLimit` 和上传大小上限约束，没有存储配额），每个账号都能添加服务商，而服务商的接口地址不经过 SSRF 防护（见[下文](#ssrf-防护)）。只有当你信任所有能访问到实例的人时，才让注册开着。

**注册会透露用户名或邮箱是否已被占用。** 这是免不了的：同名的账号建不出第二个，而系统从不发邮件，也就没法改成「请查收邮件」这样的回答。所以只要能打开开放着的注册页，就能试出某个邮箱在这里有没有账号，同一个客户端地址每小时最多试 20 次。修改自己的用户名或邮箱也会得到同样的两种回答，所以它被限制在每个账号每小时 20 次。登录接口不会透露（见[密码](#密码)）。如果「谁在这里有账号」不能让人知道，就把注册关掉。

要收回某个人的权限，超级管理员在「设置 → 用户管理」里停用或删除那个账号。停用会让它立即退出登录，数据保留：它还在排队的运行会被取消，它在团队画布上持有的编辑锁立即释放，别人不用等锁过期。删除会连同它个人空间里的画布、分享链接、资产、服务商和 Key、用量记录以及存储里的文件一起删掉，无法恢复。它在团队里做的东西留在团队；账号还是某个团队的团长时不能删除，界面会列出是哪些团队。

### 团队

团队是多个账号共用的空间（见[接口文档](api.zh-CN.md#空间与团队)）。它给上面的模型加了这些：

**团队内的角色。** 三个，和站点上的两种角色是两回事：**团长**（每个团队一个）、**管理员**、**成员**。各自能做什么是一张表，[接口文档](api.zh-CN.md#权限矩阵)里的表和服务端做判断用的是同一张。概括地说：成员干活（画布、资产、用团队的 Key 运行）；管理员另外管成员、邀请链接、服务商和 Key、品牌包；只有团长决定钱（每月上限）、谁看得到什么（团队设置）和团队本身（转让、解散）。团长看得到团队里的全部画布，包括「仅自己」的：花的是团队的 Key，创建者离开后画布要留下。

**创建团队要超级管理员授权**，按账号授予：在「设置 → 用户管理」那一行的「允许创建团队」里设置（「收回创建团队的授权」收回），或者在「设置 → 团队」的「创建团队的申请」里批准这个账号的申请。一个有授权的账号最多创建几个团队、每个团队最多多少成员是站点设置（`teamMaxPerUser`，默认 3；`teamMaxMembers`，默认 50）。

**超级管理员对团队能做什么、不能做什么。** 能：看到团队存在、它的名称、团长、成员数、画布数和运行数；设它的人数上限和并发上限；停用和重新开放；在团长解散后恢复它；在它关闭之后永久删除它；团长的账号被停用或已不存在时，指定另一名成员为团长（为此能看到成员的用户名和角色）。不能：进入团队的空间，读它的画布、提示词、资产、生成记录或 Key。超级管理员带着一个自己不是成员的团队去请求，和任何外人一样得到 404。「超级管理员管的是站点，不是别人的数据」对团队和对账号一样成立。界面上这些都在「设置 → 团队」里，那一页只有名称和数字。

**团队之间怎么隔开。**

- 每个涉及团队内容的请求都要说明作用于哪个空间（请求头 `X-Space`，或路径里的团队 id），服务端就在这个请求上现查调用者的成员身份，不缓存在会话里：**被移出团队的人，下一个请求就被拒绝**，用的还是他手里那个会话。
- 调用者不在其中的团队，返回和团队不存在时完全一样。在一个空间里用别的空间的 id 访问，得到 404，和 id 根本不存在时一样：外人如此，这个团队的成员在别处操作时如此，超级管理员也如此。列表从不混合不同空间的数据。
- 团队内，「仅自己」的画布对创建者和团长以外的所有人都是 404。
- 上面说的「共用一个进程、一个数据库、一块存储、一条队列」对团队同样成立，**公开的东西也同样公开**：文件地址对拿到地址的人公开，对外分享链接对拿到链接的人公开。团队的「私密」指的是列表和接口，不是文件地址。

**团队的 Key。**

- 只有团长和管理员能填写、更换、测试团队服务商的 Key。他们看到的和个人空间的主人一样：是否已设置和末四位，永远没有 Key 本身。
- **成员用得到、看不到**：没有任何接口向成员返回 Key、它的密文、它的末几位或它发往的地址。团队空间里只有团队的服务商；成员个人的 Key 不会用在团队里，团队的 Key 也不会用在任何人的个人空间。成员在团队的「模型管理」页看到的是服务商的名称、是否可用、「已由团队配置」和维护人，以及模型和价格；这一页对成员只读，连接测试的结果（里面可能带着上游的原话）也不给成员看。
- 所以**成员**离开时不需要换 Key。**管理员**离开或被移除时，他知道自己填过的 Key：移除接口会返回涉及的服务商，界面在移除之后把它们列出来，团长应当到上游把这些 Key 换掉。这一步 LoomCanvas 替代不了。
- 已保存的 Key 只会发往保存时的那个地址（见[下文](#静态存储时的保护)）。否则管理员可以把服务商的地址改到自己的服务器上，把别人填的 Key 骗走。

**邀请链接。** 邀请链接就是入场券：谁拿到它，谁就能以成员身份加入，不需要任何人批准。默认 7 天有效、可用 10 次，创建时可以改（接口允许 1 到 90 天、最多 1000 次或不限次数；界面上给的是 1 / 7 / 30 天和 1 / 10 / 不限），随时可以撤销。请像对待密码一样对待它：发给本人，不要发到群里。创建链接的人后来被移出团队的，他创建的链接随之失效。邀请链接不能绕过「关闭注册」：没有账号、站点又关闭了注册的人用不了它，加入页会如实说明，不提供注册入口。任何拿到链接的人在链接页面上能看到团队名称和头像、团长和邀请人的名字、人数、链接哪天到期、还能用几次，看不到团队里的任何内容。服务端只保存邀请码的 SHA-256 和一份加密副本（让管理者能再次复制链接）。

**同一时间一个人编辑。** 没有实时协作。团队画布有编辑锁：同一时间只属于一个打开着的编辑器（一个浏览器标签页），同一个账号开的第二个标签页和别人一样是只读。锁在编辑器最后一次续期后 36 秒失效（编辑器每 12 秒续一次），关掉标签页时立刻归还，能编辑这张画布的人可以接管。每次保存都带上「基于哪个版本改的」，画布已经被改过就拒绝保存。不做合并，也不会在没被看到的情况下覆盖任何东西。页面关闭时归还编辑锁，是团队相关接口里唯一不需要会话的（见[哪些是公开的](#哪些是公开的)）：它凭的是只发给这把锁的持有人的一个令牌，只能释放这一把锁。

**每月上限**（运行次数和预估金额，按成员和按团队）由服务端在提交运行时强制执行。「已用」是已成功的运行加上进行中的运行；失败和取消的会把名额退回。它的边界：金额是按团队填的价格算出的**预估**，不是上游的账单；计的是从这套实例发起的运行，不包括有人拿着 Key 在别处做的事（成员本来就拿不到 Key）。检查是精确的，同一瞬间到达的多个请求也一样：接受一条运行是数据库里的一次原子更新。按 token 计价的对话运行要跑完才知道成本，所以它在运行期间按假定的最长回答占着一笔预留；金额上限因此不会被正在跑的对话运行超出，代价是这样的运行有时会在真实成本其实放得下的情况下被拒绝。

**团队动态。** 每个团队有一份管理操作的记录：成员加入、退出、被移除，角色变更，邀请链接，服务商的添加和删除，Key 和地址的更换，价格，上限，画布的删除、恢复、接管、覆盖，分享链接，设置，解散和恢复。团长和管理员可以看；任何人都不能修改或删除其中的记录；超过 `teamActivityDays`（默认 365 天）的记录自动清除。里面没有 Key、没有地址、没有提示词。它**不是**站点的审计记录：超级管理员在团队之外做的事（停用账号、修改站点设置）不记录在任何地方，团队里的日常创作（保存、运行）也不记录。

**关闭团队。** 解散后团队立刻对所有人关闭，7 天内不删除任何东西，团长或超级管理员可以恢复；到期后团队里的一切（包括文件）被永久删除，无法找回。账号还是某个团队的团长时不能被删除，要先转让团长或删除团队。成员的账号被删除时，他退出所在的团队，他在团队里做的东西留在团队。

### 它的局限

- **没有邮箱验证。** 邮箱只要看起来像个地址、没被别人用过就行，系统不会往上面发任何东西。
- **没有双因素认证，没有单点登录。**
- **没有站点级的审计记录。** 运行按账号记录，每个团队有自己的管理操作记录（见[团队](#团队)）；但不记录谁改了站点设置、谁在什么时候被停用。
- **没有存储配额；团队之外没有花费上限。** 团队有按月的次数上限和预估金额上限，个人空间没有。其他需求请使用[计费钩子](billing-hook.zh-CN.md)，它能知道每次运行是谁发起的、在哪个空间。
- **没有实时协作。** 团队成员可以改同一张画布，但同一时间只能一个人，不存在同时编辑和合并。团队之外，分享链接给对方的是一份副本。
- 用户名和邮箱以明文存在数据库里。

在实例前面再加一层认证（代理、VPN）只能保护 `/api` 和页面，文件和分享链接本来就是要能被访问的（见下）。

## HTTPS

没有 HTTPS，密码、会话凭证、你的提示词和图片都在网络上明文传输。请在反向代理上终止 TLS，见[部署](deployment.zh-CN.md#反向代理与-https)。

应用有意不设置 `Strict-Transport-Security`（HSTS）：它无从知道自己是不是通过 TLS 被访问的。请在终结 TLS 的代理上加这个头。

在代理后面运行时，把 `TRUST_PROXY` 设成前面代理的层数（一般是 `1`）或代理的地址。不设的话，所有访问者看起来都来自代理的地址，共用同一份登录限流和注册限流，会话列表里每个会话显示的也都是代理的地址。取值是 1 到 10 的层数，或者逗号分隔的 IP、CIDR 网段以及 `loopback`、`linklocal`、`uniquelocal` 这几个名字。这里有意不提供「全部信任」的取值：`TRUST_PROXY=true` 和主机名会让服务端在启动时退出，因为每一跳都信任的话，任何客户端都能在 `X-Forwarded-For` 里自己指定地址，绕过限流。

## 哪些是公开的

下面这些不需要登录：

| 内容 | 原因 | 靠什么保护 |
| --- | --- | --- |
| `GET /files/<key>` | 分享页和上游模型得能加载素材。每个存下来的文件都是这个地址，在本地磁盘上还是在桶里都一样。 | key 里有 128 位随机数，不能列举，也猜不到。没有有效期。 |
| `GET /api/canvas-share/<token>` 和 `/share/<token>` 页面 | 分享链接本来就是这个用途。 | 256 位随机 token；可设有效期；可撤销。 |
| `GET /api/bootstrap`（原来的路径 `/api/app/bootstrap` 也能用） | 登录页和注册页需要它。 | 对未登录的请求，会透露站点名称、Logo 地址、默认语言、上传大小上限、版本号、是否开放注册（`auth.registrationOpen`）。不涉及任何人的数据，也不包括超级管理员的用户名。 |
| `POST /api/auth/register` | 注册账号。 | 限流。超级管理员关闭注册后以 `auth.registration_closed` 拒绝。 |
| `POST /api/auth/login` | 登录。 | 限流。 |
| `GET /api/team-invitations/<token>` 和 `/join/<token>` 页面 | 被邀请加入团队的人在登录之前要能看到自己要加入的是什么。 | 256 位随机邀请码；有效期；次数限制；可撤销。显示团队名称、头像、人数、团长和邀请人的名字、链接哪天到期、还能用几次，不显示团队里的任何内容。加入本身需要账号。 |
| `POST /api/workflow/<id>/lock/release` | 关掉标签页的人要立刻把团队画布的编辑锁还回去，而正在关闭的页面带不了登录凭证。 | 请求里要带这把锁的释放令牌：256 位，只发给持有人，只对应这一把锁，锁换了人就失效。它只能释放这把锁，读不到也改不了任何东西；对不上时返回和「没有可释放的」完全一样。同一个地址每分钟超过 120 次的调用不查库。 |

由此带来的后果：

- **文件地址就是通行证。** 拿到地址的人可以一直取到这个文件，登录与否都一样。地址会流出去：在分享链接里、在发给上游模型的请求里、在浏览器历史里、在截图里。
- **撤销分享链接不会删除上面的文件。** 链接失效了，但访问者如果存下了某个文件的地址，仍然能加载它。删除画布、删除资产也一样：这些都是软删除，文件还在。
- 分享链接展示的是整张画布的快照：提示词、文本节点、图片、视频，以及节点里选的模型标识（含服务商的标识前缀）。运行状态、运行号和任务号、失败详情和成本会被去掉：发布时去一遍，读取时再去一遍，复制出来的画布里也没有。
- 公开读取和复制这两个接口只认链接里的 token。分享记录在数据库里的 id 不能代替它，登录与否都一样。
- 使用 S3 存储时这一点不变：桶里的文件同样由应用通过 `/files/<key>` 提供。**桶本身可以保持私有**（`proxy` 分发）：应用用自己的凭据去读，浏览器不直接接触桶。`redirect` 分发时，对象另外还能通过桶的公开域名读到，key 同样是随机的。见[存储](storage.zh-CN.md#两种分发方式)。
- 桶里的参考素材交给上游模型时，用的是有效期一小时的**预签名地址**（`redirect` 分发时是公开地址）。拿到这个地址的人在过期前可以读取那一个对象。预签名地址按每次上游请求现做，不会存进画布、分享链接或运行记录。

如果有些素材根本不能通过地址被访问，目前的 LoomCanvas 不适合存放它们。

文件是这样提供的：内容类型取自服务端自己选定的扩展名，带 `X-Content-Type-Options: nosniff` 和沙箱化的 `Content-Security-Policy`；不是图片、视频、音频的一律以 `Content-Disposition: attachment` 下载。存下来的文件无法在应用的来源下执行脚本。本地磁盘上的文件和从桶里转发的文件（`proxy` 分发）都是这样。`redirect` 分发时，浏览器被引到桶的公开域名，那是另一个来源，响应头由它自己决定。

「按地址抓取」（`POST /api/files/fetch`）只返回图片。地址指向本实例自己的存储时也一样：存储里的视频会以 `file.image_only` 被拒绝。

## SSRF 防护

服务端有好几处会替用户去下载地址：「按地址抓取」、上游模型返回的结果、工具节点和参考图用到的外部素材、代理下载、打包下载。它们都走同一个带防护的下载器（`server/src/utils/safeFetch.js`）：

- 只允许 `http` 和 `https`，地址里不能带账号密码。
- 拒绝回环、内网、链路本地（包括云厂商的元数据地址）、运营商级 NAT、组播和保留地址段，IPv4 和 IPv6 都管，包括嵌在 IPv6 里的 IPv4 地址。
- 检查的是套接字真正连接的地址，在 DNS 解析这一步进行。所以先解析成公网地址、之后又解析成内网地址的域名（DNS 重绑定）会被拒绝。域名只要有一条内网记录就拒绝。
- 重定向由程序自己逐跳跟随，最多 5 次，每一跳重新检查。
- 每次下载都有总时限和字节上限。
- 取回来的东西按内容判断类型。自称是「图片」、实际是 HTML 页面的会被拒绝。

有三处是有意**不**经过防护的：

- **服务商的接口地址。** 它默认是服务商的官方地址。可以在服务商的高级选项里修改，指向自己网络里使用同样接口的服务是正当用法。但每个账号都有自己的服务商，也就是说，每个账号都能让服务端向内网地址发请求。注册开放时，这等于任何能访问到实例的人。这也是「不信任注册的人就关闭注册」的又一个原因。
- **存储设置里的 S3 Endpoint 和公开访问地址。** 它们由超级管理员在「设置 → 存储」里填写（或由部署者写在环境变量里），指向自己网络里的 MinIO 是正当用法。服务端的存储请求发往这个 Endpoint；连接测试会让服务端按表单里填的内容去连这两个地址。只有超级管理员能这么做。针对用户和上游给出的地址的防护没有变化。（签名地址用的 Endpoint，服务端从不去连。）内网的 Endpoint 不会泄露给上游模型：公网上访问不到的桶，它的地址绝不会交给上游，见[存储](storage.zh-CN.md#什么算公网可达)。
- **`SSRF_ALLOW_HOSTS` 里的主机。** 只有当自己网络里的上游返回了指向自身的结果链接时才需要它。列进去的每个主机，上面所有的下载功能都能访问到。只写确切的主机名或 IP，越少越好；如果有你不信任的人拥有账号，就不要用它。这个列表只管服务端自己的下载，不会让某个主机被当成上游模型能访问到的地址。

## 上传校验

- 文件类型按开头的字节判断，不看文件名，也不看客户端发来的 `Content-Type`。只保存能识别出来的图片、视频和音频格式，其中不包括 SVG 和 HTML。
- 图片会被打开读取尺寸；自称是图片却解码不了的会被拒绝。超过 1.2 亿像素的图片也会被拒绝。
- 存储 key 和扩展名由服务端决定。上传文件的名字不会出现在任何路径里。
- 大小受 `MAX_UPLOAD_MB` 限制。上传的文件放在内存里，所以这个上限也限制了每次上传占用的内存。
- 需要登录的接口，请求体在通过认证之后才解析。账号相关的接口（`/api/auth`，包括注册和登录）、分享链接相关的接口和邀请链接相关的接口（`/api/team-invitations`），JSON 最大 64 KB；保存画布 6 MB；其余 1 MB。
- 一次打包下载最多 100 个文件，单个最大 1 GiB，总大小最大 4 GiB。放不下的文件在压缩包里换成一个 `NN-<类型>-skipped.txt` 说明。
- 一个账号未完成的运行（排队中、运行中、转存中）最多 `userQueueLimit` 个（默认 200），整个实例最多 500 个，超出的以 `run.queue_full` 拒绝（HTTP 429）。
- 格式不对的请求（路径里的百分号编码有误、不支持的字符集等）返回 4xx 和 `common.bad_request`，不是 500。不认识的设置键，包括 `constructor`、`__proto__` 这类名字，以 `settings.unknown_key` 拒绝。

没有病毒扫描，除格式检查外也不做任何内容检查。

## 静态存储时的保护

| 数据 | 存放状态 |
| --- | --- |
| 账号密码 | scrypt 哈希，每个账号一个盐。任何接口都不返回。 |
| 会话凭证 | 只保存 SHA-256。从数据库里还原不出凭证。 |
| 用户名、邮箱、每个会话的 User-Agent 和客户端地址 | 明文，在 MongoDB 里。 |
| 团队邀请链接 | 邀请码的 SHA-256，以及用 AES-256-GCM 加密的邀请码（让团队的管理者能再次复制链接）。 |
| 服务商的 API Key | 用 AES-256-GCM 加密。任何接口都不返回；界面上只显示是否已设置和末四位。 |
| 「设置 → 存储」里保存的 S3 Secret Access Key，以及更早的桶的密钥 | 同样加密。不返回；界面上只显示已设置和末四位。Endpoint、桶名和 Access Key ID 是明文保存、明文返回的。 |
| 画布、提示词、设置、用量记录 | 明文，在 MongoDB 里。 |
| 上传和生成的文件 | 明文，在磁盘上或你的桶里。 |
| `SECRET_KEY`、以变量形式给出的 `S3_*` 凭据 | 明文，在环境变量里。 |

另外几项防止 Key 泄露的措施：

- **已保存的 Key 只会发往保存时的那个地址。** 在已存有 Key 的情况下修改服务商的地址（个人空间和团队都一样），必须在同一个请求里重新带上 Key，或者放弃已存的 Key；服务商类型（它同样决定 Key 发往哪里）创建后不能改；「测试连接」测的是保存着的那一份，不管请求里带了什么。存储设置同理：已保存的 Secret Access Key 只在服务地址和 Access Key ID 与保存时相同的情况下才沿用。界面上的表现是：在已存有 Key 的服务商上改「接口地址」，表单要求重新填写 API Key；在「设置 → 存储」里改了服务地址或 Access Key ID，要求重新填写 Secret。（在这条规则之前，一个请求可以保留已存的 Key，同时把服务商改到自己指定的地址上。）
- 发往上游的请求不跟随重定向，`Authorization` 头不会被带到别的主机。
- 上游如果在错误信息里把这次请求的凭据原样带了回来，显示和保存之前会先换成 `***`。
- 上游如果在错误信息里把预签名的存储地址原样带了回来，其中 `X-Amz-*` 查询参数的值（包括签名）会在显示和保存之前换成 `***`。
- 意料之外的错误只记在服务端日志里，返回给用户的是统一的提示。

自带的 Compose 文件里 MongoDB 没有开启认证，只有应用容器能访问它。如果用外部的 MongoDB，请给它配上认证和 TLS，并把凭据写进 `MONGODB_URI`。

## 浏览器端的保护

- 页面带有 `Content-Security-Policy`。脚本：`script-src 'self'`，不允许 `'unsafe-inline'`，也不允许 `'unsafe-eval'`。构建出的 `index.html` 里没有内联脚本，所以不会再加别的。（服务端启动时会读一遍构建出的 `index.html`，如果里面有内联脚本，加进策略的是它的 SHA-256 哈希，而不是 `'unsafe-inline'`；现在的构建里没有可算的。）另有 `object-src 'none'`、`base-uri 'self'`、`form-action 'self'` 和 `frame-ancestors 'self'`。样式允许 `'unsafe-inline'`，因为界面库会写 style 属性。
- 图片、媒体和网络请求（`img-src`、`media-src`、`connect-src`）有意允许任何 `http(s)` 来源，因为画布要显示来自对象存储、CDN 和用户粘贴的链接的结果，并在浏览器里下载它们。存储设置里每个公开访问地址的来源也会被明确列进去，并且跟着设置变，不用重启。眼下这不改变什么，因为本来就允许任何来源；它的作用是，将来如果收紧这些开放的来源，这几个来源仍然是允许的。
- 前端构建产物不需要 `eval`（`web/vite.config.ts` 里的 `__INTLIFY_JIT_COMPILATION__`，给 vue-i18n 用）。
- 如果前端构建产物不是由本服务端提供，而是放在别的服务器上（自己的 nginx、CDN），那台服务器要自己发送等效的策略；上面这份只有 LoomCanvas 服务端会加。
- 接口响应带 `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`，并且是 `no-store`。
- 每个响应都带 `X-Frame-Options: SAMEORIGIN`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`Cross-Origin-Opener-Policy: same-origin`，以及关闭摄像头、麦克风、定位、支付和 USB 的 `Permissions-Policy`。
- 应用不设置 `Strict-Transport-Security`，见 [HTTPS](#https)。
- 认证用的是请求头里的 Bearer 凭证，不是 Cookie，所以不存在跨站请求伪造的问题。凭证放在浏览器的本地存储里，页面里运行的脚本读得到它；把外来脚本挡在页面之外的，就是上面那条脚本策略。`CORS_ORIGIN` 默认为空：其他来源的网页不能从浏览器调用接口。

## LoomCanvas 不做的事

- **内容审核。** 提示词和结果都不经过筛查。如果有过滤，那是上游做的。你对自己生成和发布的内容负责，也要自己遵守服务商的条款和当地法律。
- **加固过的多租户隔离。** 账号之间、团队之间由接口在每次查询时隔开，但它们共用一个进程、一个数据库、一块存储和一条队列，文件地址和分享链接也是公开的。没有你自己的隔离层，它不能直接拿来给互不信任的租户做服务。
- **实时协作、评论、在线状态。** 团队共用一个空间、轮流编辑画布，见[团队](#团队)。不能按成员限制可用模型，也不能按成员分配不同的 Key。
- **邮箱验证、邮件找回密码、单点登录、双因素认证。**
- **站点级的审计日志。** 每个团队有自己的管理操作记录，站点没有。
- **私有的或会过期的文件地址。** 桶可以是私有的，但它前面的 `/files/<key>` 是公开的，也不会过期。
- **文件和数据库的加密**（服务商 Key 和存储密钥除外）。桶里的静态加密是存储服务商的功能。
- **存储配额，以及团队之外的花费上限。** 一个账号可以发起它的队列容得下的任意多次运行（`userQueueLimit`，默认同时最多 200 个未完成），文件能存多少取决于磁盘或桶有多大。在个人空间里每个账号花的是它自己添加的服务商的钱。团队可以按月限制成员和整个团队的运行次数和预估金额；金额是按团队填的价格算出的预估，不是上游的账单。其他需求请使用[计费钩子](billing-hook.zh-CN.md)（它能知道每次运行的账号和空间）和上游服务商自己提供的限额。
- **防范恶意的上游**（下载防护和内容检查之外）。你发给服务商的一切（提示词、参考素材）都交到了对方手里。
